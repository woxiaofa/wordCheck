# SOE 对接方案：从「完成度评分」到「真·发音评分」

> 状态：**方案已定稿，未开工**（2026-11-17 整理）。
> 项目当前处于停止活跃维护状态，本文档写给打算接手继续做的人：
> 路线、接口要点、计费、合规、代码落点全部铺好，照着做即可，不用再从头调研。

---

## 1. 现状与改造目标

### 1.1 现状：本机完成度评分（`honest:true`）

当前口语流程（`pkg-oral/pages/flow/flow`）的判定不判发音准不准，只判「读没读、读了多少」：

| 判定 | 规则 |
| --- | --- |
| 不合格① | `voicedMs < 180ms`（几乎没出声） |
| 不合格② | `voicedMs < min(15% × 期望时长, 350ms)`（只读了一小截） |
| 其余 | 一律合格；停顿不判错、只影响「很流畅」档 |
| 无 PCM 帧 | 一帧没采到的机型按录音时长 ≥450ms 兜底放行，标 `sampled:false` |

页面明写「不判断发音准不准」。这是刻意为之：不接 SOE 就不该冒充 AI 评分。

### 1.2 改造目标

接入腾讯云智聆口语评测（新版，SOE-N），拿到音素级评测：
准确度 / 流畅度 / 完整度 / 重音 / 声调 / 逐词逐音素标注，
替换掉完成度三档，同时保留完成度评分作为**降级兜底**（SOE 挂了不能让流程死掉）。

### 1.3 关键前提：评分器已经是可插拔的

`utils/oral-score.js` 在设计时就留了契约（详见 `docs/口语作业方案.md` 第 8 节）：

```js
// score({ frames, expectMs, refText, kind }) → { grade: 'great|ok|bad', ... , trace }
// register(name, impl) / use(name)  一行切换引擎
// normalizeRemote(remote)           远端引擎结果 → 本地 trace 结构
```

所以接 SOE 的业务改动面很小：**注册一个新评分器 + 云端签名服务 + 隐私合规**，
flow 页的进条逻辑（对了自动走、错了给「下一个」）一行都不用动。

## 2. 结论先行

**推荐路径：SOE-N（新版）+ 云函数下发一次性签名 + 小程序端直连 WSS。**

| 决策点 | 结论 | 理由 |
| --- | --- | --- |
| 引擎 | 腾讯云 SOE-N | 中文官方文档全、有官方 JS SDK 可参考协议实现、新用户 9.9 元体验包门槛极低 |
| 智聆小程序插件 | ❌ 不用 | 教育类插件**个人主体无法添加**（本项目主体即个人），且基础版已宣布下线 |
| 密钥位置 | **SecretKey 只放云函数**，端上拿一次性签名参数 | 密钥进端 = 泄漏后被人刷资源包一夜破产；腾讯云官方反复强调勿把密钥传端/GitHub |
| 音频路径 | 端上直连 `wss://soe.cloud.tencent.com` 流式上传 | 少一跳云函数中转，延迟低、云函数流量省；云函数只做签名下发，无音频过手 |
| 降级策略 | SOE 调用失败 → 自动回退完成度评分（fail-open） | 内容接口抖动不能让孩子的流程卡死；与内容安全 API 同一哲学 |
| 上线顺序 | 先体验版灰度 → 数据看调用密度 → 再买量 | 9.9 元 1 万次够摸清真实用量，别一上来买 15 万次 |

## 3. 接口要点（SOE-N，已核对官方文档）

> 来源：腾讯云官方文档《智聆口语评测(新版)相关接口》（product/1774/107497）。
> 以下为对接时最容易踩的要点，**细节以官方文档为准**。

### 3.1 连接与音频规格

| 项 | 值 |
| --- | --- |
| 协议 | WSS（一次连接 = 一段音频评测） |
| 地址 | `wss://soe.cloud.tencent.com/soe/api/?{请求参数}` |
| 音频 | 16000Hz 采样率 · 16bit · 单声道（mono） |
| 格式 | pcm / wav / mp3 / speex（**本项目录音已是 16k 单声道 PCM，天然匹配，无需转码**） |
| 发送节奏 | 建议每 40ms 发一个包（16k pcm 即 **1280 字节/包**），保持 1:1 实时率；超速或包间隔 >6 秒会被引擎断开 |
| 并发 | 默认单账号 50 路（不够再买并发包） |

### 3.2 握手参数（URL query，需 urlencode）

`secretid`（密钥 ID）、`timestamp`（秒级 UNIX）、`voice_id`（音频流唯一 id，端上生成 UUID）、
`signature`（HMAC 签名，算法见官方文档，签名时参数不 urlencode、实际请求要 encode）。

**签名由谁算？** 由云函数算。小程序把 `voice_id`（和必要时 session 参数）POST 给云函数，
云函数用 `SecretKey` 算好 `signature` 原样返回，小程序拿去拼 WSS URL。
**SecretKey 全程不出云函数。**

### 3.3 评测结果

两阶段（握手 + 识别）均返回 JSON：`code=0` 正常；`result`（SentenceInfo）为评测结果，
`final=1` 表示音频流评测结束。SentenceInfo 里有总分与逐词/逐音素明细（准确度、
流畅度、完整度、重音、声调），`normalizeRemote()` 负责把它映射成本项目的三档 trace。

### 3.4 评测模式选择

支持词 / 句 / 段落 / 自由说 / 多分支 / 关键词等模式。映射到本项目的三类素材：

| 本项目素材 | 建议模式 |
| --- | --- |
| 词级跟读（454 词） | 词模式 |
| 短句 / 两三句小段 | 句模式 |
| 口语抽查 | 词模式 / 句模式，**不给示范音**（现有逻辑不变） |

## 4. 计费（2026-11 核对，以官网购买页为准）

预付费资源包（有效期 1 年，过期作废）：

| 套餐 | 价格 | 折合 |
| --- | --- | --- |
| 1 万次 | **9.9 元**（每个 ID 限购一次） | ≈0.99 元/千次 |
| 15 万次 | 600 元 | 4 元/千次 |
| 100 万次 | 3750 元 | 3.75 元/千次 |
| 500 万次 | 17500 元 | 3.5 元/千次 |

后付费：**0.005 元/次**（5 元/千次），套餐用尽后自动转后付费。
次数计算：文本 ≤20 词（中文 ≤20 字）计 1 次；超过按每 20 词 1 次（只影响段落/自由说模式，
本项目词级与短句级都在 20 词内，**1 次跟读 = 1 次调用**）。

**用量估算**（拍脑袋但够用，上线后以真实数据修正）：
一次完整口语流程 = 9 条带读 + 5 题抽查 = **约 14 次**（重读的失败条目另计）。
一个 40 人班级每天跑一轮 ≈ 560 次/天 → 1 万次体验包 ≈ **17 天**，后付费 ≈ **2.8 元/天**。
也就是说：验证期 9.9 元够了；真有老师整班用，月成本约 85 元，必须先解决「谁付这笔钱」
（这正是 `docs/角色体系与商业模式.md` 里「使用者、分发者、付费者是三个人」死结的具体化）。

## 5. 儿童语音合规（比技术更难的部分）

用户是小学生，录音是**未成年人个人信息**，上传即出端。这几条是提审与法律层面的硬门槛：

1. **隐私指引改写**：《用户隐私保护指引》需从「录音仅存本机、不上传」改为
   「录音上传至腾讯云智能语音评测服务用于发音评分」。**原来的表述是本项目的重要卖点，
   接 SOE 后必须诚实改掉，且要走重新提审**。
2. **单独同意/监护人同意**：面向 14 岁以下儿童的个人信息处理有更严格要求
   （未成年人个人信息保护相关规定），首次使用 SOE 评分前应弹独立告知，
   不能混在通用隐私弹窗里一句话带过。
3. **最小化存储**：音频流式上传、评测完即弃，**不要落云存储**（现在跟读录音本来就不落盘，
   保持这个性质）；trace 里只留分数与逐词标注，不留音频。
4. **供应商条款**：腾讯云侧确认该服务的儿童数据处理合规口径（处理者角色、留存期），
   留档备查。
5. **提审备注**：说明评测用途、不留存音频、有监护人告知机制。若审核卡「儿童语音上传」，
   Plan B 是把 SOE 做成**仅书面模式可用**的可选开关（默认关），等主体升级企业后再全量开。

## 6. 代码落点（文件级清单）

| 文件 | 改动 | 量级 |
| --- | --- | --- |
| `cloud/functions/soe/index.js` | **新建**：action `sign`（校验登录态 → 生成 voice_id → HMAC 签名返回）、`quota`（按用户/按天限次，防刷） | M |
| `cloud/functions/soe/config.json` | 声明权限（SOE 是直连 WSS，不需要 openapi；只需普通调用权限） | S |
| `miniprogram/utils/oral-score.js` | 注册 `soe` 评分器：WSS 连接、40ms 分包发送（复用 `oral.js` 的 PCM 帧）、`normalizeRemote` 映射 SentenceInfo → 三档 trace | L |
| `miniprogram/utils/oral.js` | 录音帧直接喂评分器（已有 `onFrameRecorded` 1280B 对齐，几乎不用动） | S |
| `miniprogram/pkg-oral/pages/flow/flow.js` | 评分器 `use('soe')` 切换；SOE 失败降级回调；隐私二次告知弹层 | M |
| `miniprogram/pkg-oral/pages/flow/flow.wxml` | 逐词染色视图（绿/黄/红/漏读，参考官方 demo 交互）；告知弹层 | M |
| `tests/oral-score.test.js` | 假 WSS / 假 SentenceInfo 全量走一遍 + 降级变异自证 | M |
| `tests/launch.test.js` | 新增守护：`SecretKey` 不许出现在 miniprogram/ 任何文件 | S |
| mp 后台 | 隐私指引改写 + 重新提审 | 人工 |

**防刷限次是必须的**：签名接口虽然不带 SecretKey，但每次 WSS 调用消耗你的资源包。
云函数 `sign` 前先查当日次数（如每用户每日 N 次、无班级用户更低），超出即拒绝——
不然小程序被人扒了协议就是无限刷。

## 8. 备选方案对比（为什么不是别的）

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| **腾讯云 SOE-N（推荐）** | ✅ | 见上文；新用户 9.9 元门槛低、协议文档全、官方 JS SDK 可参考 |
| 腾讯云 SOE 旧版（product/884，InitOralProcess/TransmitOralProcess） | ⚠️ 不选 | 新版是其替代路线，旧接口无演进预期，别新项目接旧协议 |
| 智聆口语评测小程序插件 | ❌ | 教育类插件个人主体加不了；基础版下线 |
| 科大讯飞语音评测 | 备选 | 能力相当，但个人开通与计费门槛更高；若腾讯侧合规谈不拢再换，`oral-score.js` 契约保证切换只改一个文件 |
| 本地离线（whisper 等） | ❌ | whisper 是识别不是评测，做不了音素级正误判断；可用的离线评测模型（如 CPC 系）在小程序端跑不动；官方离线 SDK 仅 Android/iOS 原生、约 80MB，与小程序形态不符 |
| 维持现状（完成度评分） | ✅ 已是现状 | 无成本、零合规负担；缺点是不判准不准，对「认真读了但读错了」的孩子没有纠音价值 |
