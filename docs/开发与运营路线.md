# 开发与运营路线：先测试，再云端，再商业化

> 本文回答一个问题：**从现在这个"本地版已完整"的状态，到能收钱的产品，接下来每一步做什么、做到什么算过关。**
> 配套阅读：`docs/实施手册.md`（技术细节）、`背单词教练小程序-可行性与产品方案.md`（商业逻辑）。

## 一、现状一句话

学生端的"学习 → 自评 → 抽查 → 错词回流"闭环在**本地数据层面已经完整可用**（含 115 项自动化测试），
但云端（登录、任务快照、真实词库）尚未打通，教练端和支付完全未动。
**当前版本最大的价值是：不依赖任何后端，就能拿给真实用户验证体验。**

## 二、路线总览

### 表 |

阶段 | 内容 | 判据（做到才算过） | 预估
**0 · 先测试** | 真机自测 + 3–5 人内测（就用本地版） | 测试清单全过 + 内测用户能独立完成"学一轮→抽查一组"且无需解释 | 3–5 天
**1 · 云端打通** | user/task 云函数、建库建索引、部署、导入词库、接发音 | 数据云端可见；换设备登录后进度不丢；断网仍可用（本地缓存） | 1 周
**2 · 内测放量** | 30–50 个种子用户跑 2 周 | 日抽查完成率 ≥ 40%；次日留存 ≥ 35% | 2 周
**3 · 教练端 MVP** | 布置任务、学员进度、催学文本 | 教练布置后，学员首页当天出现任务卡片 | 1–2 周
**4 · 支付与押金** | 会员、押金对赌（需企业主体 + 商户号） | 沙箱支付走通，回调幂等 | 3–5 天
**5 · 合规上架** | 隐私协议、类目、审核提交 | 审核一次通过 | 3 天

**核心原则：阶段 0 和 1 可以并行（测试的反馈决定词库难度和文案），但阶段 3（教练端）必须等阶段 2 的数据说话。**
教练端是差异化卖点，也是最重的投入——如果免费学生端的留存都起不来，先别做教练端。

## 三、阶段 0：先测试（现在就做）

### 3.1 真机自测清单（开发者自己过）

- [ ] **首次使用**：引导卡出现（约 1 秒后、不遮挡）、点"开始学第 1 轮"进入示范卡、上滑一次进入正式学习、之后永不再现
- [ ] **iOS + Android 各过一遍**：手势（点开/上滑）、26 键键盘（含退格）、8 秒自动揭晓不自动跳词
- [ ] **三档反馈**：选"没想起来"的词，10 分钟内在同轮复习队列里重现
- [ ] **学完一轮**：出现"下一关：抽查"引导，点击能跳转
- [ ] **抽查全流程**：三题型各至少 1 道、交卷后逐题对照正确、错词进入错词本
- [ ] **跨天边界**：23:50 学几个词 → 00:10 重新打开，任务归到新的一天（这是 time.js 存在的意义，必须验）
- [ ] **断网**：飞行模式下学习页正常（本地兜底）、抽查正常（本地判分）
- [ ] **打卡口径**：完成 80% 后首页进度文案变化、连续天数正确累计

### 3.2 内测（3–5 个真实用户：家长 + 孩子）

找真实的"家长付费意愿"用户，观察三件事，不要问"你觉得怎么样"：

1. **孩子能不能不经解释独立走完**"学一轮 → 抽查一组"——每次卡住的地方都记下来
2. **家长看完抽查结果页的"给家长看的一句话"是什么反应**——这是付费转化的原型触点
3. **第二天自己回来吗**——不发提醒，看自然回访，这是留存的最诚实信号

### 3.3 阶段 0 的产出决定三件事

- 词库难度与体量（第一批导入多少词、什么词表）
- 首页/学习页文案的二次修订
- 是否值得进阶段 1（如果没人愿意用，云端白搭）

## 四、阶段 1：云端打通（技术清单）

按依赖顺序：

1. **`user` 云函数**（login 动作，首次调用自动建用户）——review/quiz 能真正跑起来的前提
2. **建集合 + 索引**（清单见实施手册 4.2，最关键的三个）：
   - `user_word_state` 的 `(user_id, next_review_at)` —— 查今日到期词
   - `user_word_state` 的 `(user_id, word_id)` 唯一 —— 防重复状态
   - `daily_tasks` 的 `(user_id, task_date)` 唯一 —— 任务快照幂等
3. **`task` 云函数**：今日任务组装与快照冻结搬上服务端（客户端本地队列只是过渡形态）
4. **部署 review / quiz / task / user 四个云函数**，替换 `utils/cloud.js` 的 `ENV_ID` 和 `project.config.json` 的 appid
5. **词库导入**：先小后大（内测反馈决定的第一批 500–1000 词），释义与例句必须自撰或已授权
6. **发音源**：预生成音频放云存储，填 `words.audio_file_id`（听写题的可用性依赖它）
7. **离线补传**：把 `submitReview` 的静默失败改为压入补传队列（约定第 2 条的完整落地）

## 五、阶段 3：教练端 MVP（范围刻意收窄）

第一版只做三件事，不做班级管理、不做排课：

1. **布置任务**：教练选词表 + 设截止日期 → 学员首页当天出现任务卡片
2. **学员进度**：一个只读列表，看每个学员的完成量和抽查正确率
3. **催学文本**：一键生成"你家孩子昨天 10 个词对了 7 个，错的这 3 个今晚还得过一遍"——只生成文本，教练自己复制发微信（不做推送，绕开订阅消息的配额限制）

**为什么催学只做文本**：微信订阅消息一次授权只能发一条，做"自动催"在小程序里是死路；而教练手动转发一条带数据的真实文本，比系统群发有效得多——这条路径反而更符合真实使用场景。

## 六、运营路线

### 6.1 定位（对外只说一句话）

> 不是又一个背单词工具，是**"孩子背没背，家长看得见"**的抽查督促。

竞品全是"学生自用工具"，没人做"结果可被第三方看见"这个闭环。所有运营动作都往这句话上靠。

### 6.2 冷启动：从教练侧切入，不从学生侧

- **种子教练**：找 3–5 个一线英语老师 / 有私域的家长群 KOC，免费用教练端，条件是每人带 10–20 个学员
- 老师的动机现成：不用自己出题、改题，抽查结果直接可转发给家长——**帮老师省事，比帮学生提分更好卖**
- 家长群是天然分发场：一张"本周错词榜"截图就能带来询问

### 6.3 裂变触点（产品里已经埋好，运营时激活）

- 抽查结果页的"给家长看的一句话"→ 后续升级为可保存的分享卡片（阶段 2 做周报卡片时一并做）
- 连续打卡天数 → "坚持第 N 天"分享图（背单词品类的经典裂变，成本低）

### 6.4 收费设计（对应产品方案的四类人群）

- **学生端永远免费**（含抽查不限量）——免费才有规模，规模才有数据
- **教练端订阅制**：免费带 5 个学员，超出按月收（教练是付费意愿最强、付费能力最确定的一端）
- **家长押金对赌**：家长交押金，孩子完成率达标全返——转化率最高的形态，但依赖阶段 4 支付 + 教练端都已就绪，放最后

### 6.5 北极星与护栏指标

- **北极星**：每日抽查完成率（学习可以造假自评，抽查不能——这是产品真实价值的代理指标）
- 护栏：7 日留存 ≥ 25%、抽查组均分不持续下降（下降说明词库难度或 SRS 参数有问题）

## 七、现在就可以做的三件小事

1. 把本文阶段 0 的自测清单在真机上过一遍（不需要任何账号和环境）
2. 圈定 3–5 个内测家庭，约好两周的观察期
3. 与此同时开写 `user` 云函数（它不依赖任何内测结论，属于确定性工作）
