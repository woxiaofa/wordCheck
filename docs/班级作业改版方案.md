# 班级作业改版方案：下一步的可能性

> 状态：**方案存档，未开工**（2026-11-17 整理）。
> 项目已停止活跃维护，本文档写给接手者：现状盘点、六个改版方向（每个都标了工作量与风险）、
> 与既有硬约定的冲突点、优先级建议。做哪个、先做哪个，按你手上的真实用户来定。

---

## 0. 判定线前置（别跳过）

历史拍板的达标线：**拿到「一本非外研四上的词库需求」或「一个愿意整班试用的老师」**。
改版是给真实用户做的，不是给想象中的用户做的。没有人整班试用之前，
下表任何方向的优先级都应视为「存档」而非「待办」。

---

## 1. 现状盘点

### 1.1 教练端已有能力

| 能力 | 说明 | 落点 |
| --- | --- | --- |
| 建班 / 加入 | 教练建班拿邀请码，学生输码加入 | `class` 云函数、`pages/class` |
| 布置任务 | 按教材单元（起点滑杆 + 一键续接上次）或自定义词单（点词可删、搜索可加） | `class.assign` |
| 自动分天 | 一次设定分 N 天发完（如 42 词 4 天 → 每天约 11 词），定时器每天 08:00 触发 | `assign_plans` 集合、幂等靠 `last_date` |
| 学员状态 | 列表一眼看出谁做了/没做，累计词数 | `students` / `review_logs` |
| 催学 | 一键生成催学文案，复制转发 | `class` |
| 每日简报 | 教练订阅推送 | `brief_subs` 集合、订阅消息 |
| 报告 | 学员报告页，A4 长图存相册转发家长 | `pages/report` |

### 1.2 数据面（真实集合名，改版前先认清）

`classes`、`students`、`users`、`words`、`assign_plans`、`daily_tasks`、
`review_logs`、`user_word_state`、`brief_subs`。

### 1.3 现状的两个真实短板

1. **布置是「全班一刀切」**：一个班只能有一份进行中的布置口径，同一个任务打到每个学生；
   而真实班级天然分层（快的孩子吃不饱、慢的孩子跟不上）。
2. **错误数据只回流到学生本人**：错词驱动的是他自己的复习队列，老师端只能看到「谁错得多」
   的聚合，不能基于错词发起动作。

## 2. 六个改版方向

> 工作量口径：S = 一两天 / M = 一两周 / L = 一个月级。
> 每条都列了「会不会破坏硬约定」——见第 3 节，那六条比任何功能都重要。

### 方向 A · 分层布置（按学生小组布置不同词单/数量）

- **解决什么**：全班一刀切 → 教练把学生拖进 A/B/C 组，每组布置不同单元范围或词数。
- **数据模型**：`students` 加 `group` 字段；`assign_plans` 从「班级维度」改为
  「班级 × 组维度」，或引入 `target: { kind: 'class'|'group'|'student', id }`。
- **云函数**：`assign`、`planCreate`、`dailyAssign`（定时器要按 target 分发）。
- **前端**：布置页加「发给谁」步进；学员列表加组筛选。
- **工作量**：M。**风险**：`dailyAssign` 的幂等键要从 `classId+date` 扩成
  `classId+target+date`，改错会漏发或重发——幂等测试要先行。

### 方向 B · 错词驱动加练（老师可发起「全班重练 Top 错词」）

- **解决什么**：把已有的错词聚合变成动作——教练端一键把「全班错得最多的 10 个词」
  生成一份加练任务，注入各学生当天的 `daily_tasks`。
- **数据模型**：复用 `assign`，只是词单来源换成 `review_logs` 聚合；加练任务需标记
  `source: 'wrong-top'` 与 `deadline`，避免挤掉当天主线任务。
- **工作量**：M。**风险**：与「每日任务冻结快照」约定的交互——冻结当天不再变，
  加练应该**以追加题项的方式进当天任务**，而不是改写快照；这是本方向最需要想清楚的一点。

### 方向 C · 作业截止与补做

- **解决什么**：现在缺了日期维度的约束——没做就是没做，昨天欠的今天可以做也可以无限拖。
  加 `deadline`，逾期任务进「补做」区，教练端能看清欠账。
- **数据模型**：`assign_plans` 加 `deadline`；`daily_tasks` 状态机加 `overdue`。
- **工作量**：S~M。**风险**：低。这是六个方向里**性价比最高**的一个，
  如果只做一个，做这个。

### 方向 D · 听说读写分项作业

- **解决什么**：现在口语是背词流程的一部分（带读→抽查→背词→报告），教练不能只布置
  「今晚只练口语」。分项布置让四种能力各自成任务、各自出报告。
- **数据模型**：`daily_tasks` 的 item 结构加 `skill: 'word'|'oral'|'spelling'|'listen'`；
  口语任务的素材引用 `data/oral-lesson.js` 的课结构。
- **工作量**：L。**风险**：口语流程（flow）现在是「贯穿式」设计，拆散它要重新设计
  引导路径；没有整班老师反馈之前不建议动。**前置依赖**：方向若与 SOE 对接（见
  `docs/SOE对接方案.md`）同时做，先做 SOE——分项口语作业没有真评分支撑价值有限。

### 方向 E · 家长只读视图

- **解决什么**：现在家长看报告靠教练/学生转发长图，转一次看一次。升级为
  「家长绑定学生 → 订阅式接收每日/每周摘要」，只读、不可操作。
- **数据模型**：`users` 加家长身份与绑定关系（一个学生可绑多位家长）；摘要生成复用
  `learn-summary`。
- **云函数**：新增家长订阅 action，复用订阅消息通道（`brief_subs` 同款）。
- **工作量**：M。**风险**：合规面扩大——绑定孩子意味着收集家长与孩子的关系信息，
  隐私指引与未成年人保护条款都要跟上；**比方向 C 难的不是代码，是合规**。

### 方向 F · 多班 / 多教练协同

- **解决什么**：一个机构多个老师管多个班（班主任 + 任课）现在做不到。
- **数据模型**：`classes` 加 `coaches[]`（角色区分主/副）；权限校验从「单教练」改
  「教练列表」。
- **工作量**：S~M。**风险**：低，但需求密度也低——单人教练场景下用不上，
  只有真拿到机构客户才值得做。

## 3. 任何改版都不能破坏的硬约定

来自 `docs/设计约定.md`，改版评审时逐条对照：

1. **抽查答案不下发客户端**——新题型、新作业类型一律遵守；
2. **所有提交类接口幂等**（`clientReqId` 先查后写）——方向 A 改幂等键是高风险点；
3. **「今天」只由 `shared/time.js` 决定**——补做、截止日期的时区判定全部走它，
   不许散落 `new Date()`（UTC+8 跨天边界有 13 项测试锁着）；
4. **每日任务冻结快照，当天不再变**——方向 B 的加练必须设计成「追加」而非「改写」；
5. `user_word_state` 唯一索引 `(user_id, word_id)`——分项作业不改变这个结构；
6. **词库内容只用自撰或已授权**——老师自定义词单更要注意：内容安全检测
   （`seccheck.checkText`）必须继续拦在入库前，这是 2026-11-16 提审被拒后的合规底线。

## 4. 迁移到自建服务器 + MySQL 的可能性

长期看，云开发的锁定成本（免费环境到期、按量付费不可控）是真实的——
本项目的设计从一开始就留了退路，迁移是「重写适配层」而不是「重写产品」：

- **业务规则全部在 `shared/`**（前端与云函数两份副本由脚本生成，单一真相来源），
  迁移时原样带走；
- **所有数据库读写只在云函数里**，页面永远通过 `utils/cloud.js` 调用；
  迁移 = 云函数的 action 逐个换成 HTTP 接口 + `utils/cloud.js` 底层从
  `wx.cloud.callFunction` 换成 `wx.request`，**页面层零改动**；
- 建议顺序：先落 MySQL 表结构（`classes` / `students` / `users` / `assign_plans` /
  `daily_tasks` / `review_logs` / `user_word_state` 一一对应），再按「先读后写」
  逐 action 切流；幂等键、时区函数、答案不下发三条约定原样带过去；
- 参考文档：`docs/数据同步设计.md`（本地与云端的同步口径）、`docs/实施手册.md`（集合与索引清单）。

工作量级：L。**触发条件**：云开发成本失控或需要接 SOE 等需要长连接/自签鉴权的服务时再启动，
不要为了「技术栈洁癖」提前迁。

## 5. 优先级建议

| 情形 | 先做什么 |
| --- | --- |
| 有了一个愿意整班试用的老师 | **C（截止与补做）→ A（分层）→ B（错词加练）**。C 最便宜且老师立刻有感 |
| 只拿到词库需求、没有班级用户 | 不做班级改版；把力气花在词库接入流程与发音音频自动化上 |
| 拿到机构客户 | F（多教练）→ E（家长视图，合规先行） |
| 决定接 SOE 真评分 | 见 `docs/SOE对接方案.md`；先 SOE 后方向 D |

一句话：**这份文档存在的意义不是「待办清单」，而是让接手的人不用重新调研一遍——
每条路都标好了工作量、风险和会踩碎哪条约定。**
