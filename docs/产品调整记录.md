# 产品调整记录

> 记录每一次影响用户可感知体验的调整：改了什么、为什么改、放弃了什么。
> 原则：产品文案与实际行为必须一致——流程改了，所有描述旧流程的文案同一天改掉。

## 2026-10-08 第四批：教材三级结构 / 老师端一张表 / 家长简报 / 离线可练

### 调整 10：词库从"一个标签"升级为「版本 → 册 → Unit」三级结构

- **过程**：`scripts/data/waiyan4a.js` 增加 `module.exports.units`（10 个 Unit 的名字落到数据上，
  不再靠注释里的人肉 parse）；`scripts/build-waiyan.js` 重写：给每个词条打
  `book / volume / unit / unit_order` 四个字段，同时单独生成 `miniprogram/data/booktree.js`
  （版本-册-单元目录树，≈2KB，端上离线可读）。Unit 1~10 词数 = 15/9/20/14/9/9/9/8/8/8 = 109。
- **原因**：老师布置的口头禅是"今天布置 Unit 3"，不是"给我 20 个中考词"。
  在此之前我们用 tag 近似，"Unit 3"只能靠老师自己心里记是哪几个词。
- **关键设计**：排序用 `unit_order`（课本顺序）而不是 `freq`（全局词频）——
  freq 会把同一个 Unit 的词打散到不同难度段，孩子练的顺序跟课本对不上。
- **代价与取舍**：已存在的词**只补标签不建第二条**（避免同一个词在库里出现两次）；
  新进库的词 freq 从 7000 起，不挤占"全部"取词的前排。非教材词**不带**这四个字段
  （字段含义不暧昧：没有 = 不属于任何教材）。

### 调整 11：老师端「一张表」——谁没交 / 错哪几个词 / 错法 / 字母混淆

- **过程**：`cloud/functions/class` 的 `assignments` 返回体新增 `pending_names`（没交作业的人）
  与 `class_wrong`（全班错词快递)：`wrong_top`（词 + 次数 + 中文释义）、
  `mistake_top`（错法归类）、`letter_top`（哪个字母总被写成哪个）、`counted`（依据多少条记录）。
  前端 22.coach 把这张表铺成一行一行，作业卡上直接写"3 人未提交 / 错得最多：street 街道（4 次）"。
- **为什么这是护城河**：错题的原料是**孩子实际敲出来的字符串**（客户端上传 `wrong_answer`），
  拍照批改类产品只能判"这行错了"，没法告诉老师"o 总被写成 0"。
- **关键设计**：错因判定抽成 shared 模块 `wrong.js`，前后端共用同一份，
  否则错题本说 A、班级报表说 B，老师会直接不信这个产品。判定**宁可粗判不可瞎判**：
  刻意**不做** `1→l` / `0→o` 归一，否则小学最常见的"o 写成 0"会被判成对的。

### 调整 12：离线也能练（作业快照 + 本地算进度）

- **过程**：新增 `miniprogram/utils/asgcache.js`：每次拉取成功就把最新作业存本机
  （只存练得上用的：id / name / ids / count / deadline / unit_label），失败才读它；
  失败时在本地按 `word_state_mirror` 口径算进度，界面标说
  **"断网中：还能接着练，N 条记录联网后自动补传"**。
- **原因**：用户反馈"没做发布任务之前可以离线，现在好像不行了"——
  作业搬到云端之后，一次网络抖动孩子就没得练，这是云端化最不能接受的副作用。
- **铁律**：**成功永远以云端为准**，缓存只在失败时兜底。不以离线可用性换在线正确性；
  没网也没快照时退回本地默认词库，保证永远有得练。快照 30 天过期标 stale（还能练但要提示）。

### 调整 13：家长简报触达（订阅消息 + 分享卡片）

- **过程**：① 分享卡片当天就能用（`onShareAppMessage`，零成本不需要模板）；
  ② 订阅消息：`wx.requestSubscribeMessage` 用户点同意 → 服务端在 `brief_subs` 记账 →
  `subscribeMessage.send`，每天 20:30 定时触发器推一次，同一天不重发；
  ③ **没配模板 ID 时显式降级**（返回 `NO_TEMPLATE` / `skipped`），绝不"看着成功其实没生效"。
- **原因**：用户说"我们暂时家长和老师是一个角色"——同一个微信号既布置又收简报，
  所以简报必须能推到这个微信手上，再靠分享卡片转给真正盯孩子的人。
- **关键设计**：模板内容复用 `shared/summary` 那一句话（全国特征是"学了多少 / 掌握几题"，
  不是"今天很棒哦"）；定时触发 `event.Type === 'Timer'` 时**没有 OPENID**，入口必须先认这个分支；
  一个人授权失效不能拖垮整批（`failures[]` 记录，其余照发）。
- **退订永远可用**：退订分支写在模板校验**之前**——模板被摘掉时回"服务端没配模板"
  等于把用户锁在里面再也退不掉。

### 保持不变的（避免误改）

- 旧 API 全部不动：`getWords / getKey / list / currentName` 照旧能按 tag 取词，
  老的按 tag 布置的历史作业记录既不报错也不被改写。
- `tag` 方式布置的行为完全不变（库里也不写 unit 字段），三级结构纯粹是新增能力。
- 抄写不计判定、SRS 间隔、"学过即算"等既有口径。

## 2026-10-07 第三批（晚）：详情页「抄写」+ 拼写超时按字母数

### 调整 8：不会/答错的详情页加「✍ 抄写一遍」（可抄多遍）

- **过程**：详情页在「🔊 跟着念一遍」旁并排加「✍ 抄写一遍」，点击展开输入区 +
  自绘键盘（照着上面的词拼），抄对记一遍并清空让下一遍从头来；
  抄错不清空，直接提示"第 N 个字母应该是 x，你写的是 y —— 改一下再确定"。
  键盘难度随抄写遍数递进：easy（仅正确字母）→ medium（含易混字母）→ hard（全键盘）。
- **原因**：念是耳朵记、抄是手记，两样都做了才算真过一遍；之前详情只有"听"，
  动手这一环缺了。抄写**不计入判定**（它只是练习，不伪造一次"学会了"的记录）。
- **代价**：详情页变长，故键盘默认收起，只有点「抄写一遍」才展开。

### 调整 9：拼写/听写超时改为按字母数计算

- **过程**：从一刀切 25 秒改为 `6 秒起步 + 每个字母 2.5 秒`，夹在 12~45 秒之间
  （"想了很久"提示在超时的 60%）。选择题（认）仍是 5 秒提示 / 10 秒超时——
  认的是意思，跟单词长短无关。
- **原因**：用户反馈"可以按字母数量调整，大概每个字母 2-3 秒"。一刀切 25 秒的毛病：
  3 个字母的词太宽松（孩子干等着被判超时），12 个字母的词太紧（还没敲完就记不会）。

### 保持不变的（避免误改）

- 选择题（认）的 5 秒提示 / 10 秒超时：它是"认意思"，不是"敲字母"。
- 抄写不计入学习判定与错题本：它是练习动作，不是一次作答。

## 2026-10-07 第二批（下午）：背词 + 抽查合并为「认 → 写」两阶段

### 调整 1：主学习流从"翻面自评"改为「认 → 写 → 巩固」

- **过程**：用户反馈"背单词大改版，之前上滑看词不要了，上来就是抽查"。
  先「认」（读音 + 单词 + 音标，两个中文释义二选一，另有【不会】诚实按钮），
  再「写」（读音 + 音标 + 中文释义，自绘键盘拼英文，键盘难度简单 → 复杂，
  拼错自动降回最简单），没拿下的词进入巩固轮反复测到全对（上限 5 轮）。
- **原因**：翻面自评把判分权交给孩子，"看了点了会了"就算学会，家长无法信任；
  二选一 + 拼写是可判分的客观题，答对答错由程序判定，结果才可信。
- **代价**：旧"学习页"（study）退为备用路径；其交互组件（上滑卡片、三个自评按钮）保留但不再是主流程。

### 调整 2：底部导航去掉"抽查"

- **过程**：用户实锤"导航抽查还在"。footer-nav 移除抽查项，只留 今日 / 背词 / 数据 / 班级。
- **原因**：背词已含抽查，再留一个 tab 会让家长以为这是两条独立练习线。
  独立抽查页（quiz，交卷制考试模式）保留，入口在首页"去抽查 · 检验真实水平"。

### 调整 3：荣誉榜加"今日 / 本周 / 本月最快"

- **过程**：rank 云函数为每个成绩 key 维护 day / week / month 三只"期内最快"桶，
  跨周期自动重开；完成页展示三行小榜（榜首昵称 + 用时 + 我的名次）。
- **原因**："找到每个人的最优最好"——只留总榜会永远被最快的人占着，周期榜让普通孩子也有登顶机会。

### 调整 4：答题时长如实上报（学习简报时间修复）

- **过程**：此前 review_logs 从不传 durationMs，云端全 0，简报永远"经过 1 分钟"。
  现在背词页逐词记录用时（含看详情、跟读的停留时间）上报。
- **原因**：简报是发给家长看的，时间虚报一次，整份简报的可信度就归零。

### 调整 5：发音能力整改（分包 + 补齐 + 大小写）

- **过程**：① 音频 + 三个练习页整体迁入 `pkg-media` 分包（主包 1.6MB → 180KB，
  分包 1.7MB，配 preloadRule 预下载）；② Piper 增量生成外研四上 100 词 mp3
  （32kbps，新增仅 288KB），400 词全有本地发音；③ 修复大写词（China / Halloween…）
  查清单被误判无音频的 bug（清单查找改大小写不敏感，播放路径保留原样文件名）。
- **原因**：主包 2MB 红线已顶死，词库无法扩充；无音频词出听写就是"哑巴题只能错"；
  大写词哑巴是生成清单后新引入的回归，测试当日抓住。

### 调整 6：按钮规范（用户定稿）：不写死宽度

- **过程**：`.btn` 从 `width:100%`（更早是默认宽度）改为**宽度自适应文案 +
  左右 padding 撑起 + 整颗居中**，胶囊圆角；宽屏（.wide）同规范按 px 缩放。
  `width: fit-content` 不被支持的环境该行被丢弃、自动回退为撑满，不会更坏。
- **原因**：iPad Pro 实锤按钮被裁成一条贴边。写死宽度的方案在不同端上总有例外，
  自适应 + padding 是对内容最鲁棒的形态；用户明确指定此规范，全应用统一执行。

### 调整 7：首页文案全面对齐新流程

- **过程**：首启卡的"先快刷：看单词选意思…"改为"先认后写：听读音选出意思，
  再听音把单词拼出来…"；"今天怎么学"三步从"翻面自评"改为「认」「写」「错词回炉」；
  进度口径说明从"每个词评价一次"改为"「认」「写」都过了才算完成"。
- **原因**：流程合并当天起，首页所有描述旧流程的文案都在撒谎；产品可信度
  来自"说的和做的一致"。

### 保持不变的（避免误改）

- 独立抽查页的"当场判分 + 限播 3 次"：它是**考试模式**，限时听音是刻意设计，
  与背词页"无限听音"的练习定位相反，不要"统一"它。
- SRS 档位与间隔（10 分钟 → 1 天 → … → 120 天）与"学过即算"的完成口径。
- 数据页、错词本、班级作业的既有文案口径。
