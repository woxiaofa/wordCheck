# 云开发部署指南（从零到家长能发任务）

> 对应 `docs/实施手册.md` 第八章批次 0~1。全程约 30 分钟，其中大半是等控制台反应。
> 前提：云环境已开通（工具「工具」菜单 → 云开发，或 tcb.cloud.tencent.com）。

## 一、填环境 ID

1. 打开云开发控制台 → 左下角「设置」→ 环境设置，复制完整环境 ID
   （形如 `cloud1-9gxxxxx123456`，不是环境名 `cloud1`）
2. 改 `miniprogram/utils/cloud.js` 第 11 行：

```javascript
var ENV_ID = 'cloud1-xxxxxxxx';   // 换成你的
```

## 二、建集合与索引

云开发控制台 → 数据库 → 「+」逐个创建集合（权限都选**仅创建者可读写**）：

| 集合 | 用途 | 本阶段必须 |
| --- | --- | --- |
| `users` | 用户 | ✅ |
| `words` | 词库 | ✅ |
| `user_word_state` | 每用户每词的 SRS 状态 | ✅ |
| `review_logs` | 复习明细 | ✅ |
| `daily_tasks` | 今日任务快照 | ✅ |
| `request_dedup` | 提交幂等去重 | ✅ |
| `quiz_sessions` / `quiz_items` | 抽查会话与逐题记录 | ✅ |
| `classes` | 班级（家长端，邀请码加入） | ✅（批次 1：class 函数） |
| `assignments` | 布置的作业 | ✅（批次 1：class 函数） |
| `brief_subs` | 每日简报订阅关系 | ✅（批次 1c：简报推送） |
| `word_books` / `word_examples` / `checkin_records` / `achievements` / `assignment_progress` / `orders` / `deposits` | 后续批次 | 可先不建 |

然后给已建的集合加索引（数据库 → 集合 → 索引管理 → 添加）：

| 集合 | 索引 | 类型 |
| --- | --- | --- |
| `user_word_state` | `user_id + next_review_at` | 非唯一 |
| `user_word_state` | `user_id + word_id` | **唯一** |
| `daily_tasks` | `user_id + task_date` | **唯一** |
| `review_logs` | `user_id + created_at`（倒序） | 非唯一 |
| `quiz_items` | `user_id + created_at`（倒序） | 非唯一 |
| `words` | `word` | **唯一**（防止词库重复导入） |
| `words` | `volume + unit + unit_order`（分行三行添加） | 非唯一（**按 Unit 布置必需**） |
| `classes` | `code` | **唯一**（邀请码查班） |
| `assignments` | `class_id + created_at`（倒序） | 非唯一 |
| `users` | `class_id` | 非唯一 |

> ⚠️ 索引避坑（实测踩过）：
> 1. **索引字段是 `word`（单数）**，不是集合名 `words`——填错会导致所有记录该字段为 null，唯一索引在导入第 2 条时就报 `E11000 duplicate key`。
> 2. **索引名称在同一集合内必须唯一**，第二个索引起个新名字（如 `idx_user_word`）。
> 3. **多个字段要点「+」分行添加**（user_id 一行、word_id 一行），不要在一个框里填 `user_id + word_id`。
> 4. **`words` 的 `volume + unit + unit_order` 是新增索引**（2026-10-08 教材三级结构）。
>    没建它，按 Unit 布置仍能布置，但客服端查询要走全表扫描，词多了会超时。

## 三、导入词库（454 词 · 2026-10-10 换版后）

### 3.1 推荐路线：用 seedwords 一次性工具（自带回查证据）

控制台「导入」也能做，但导完没人知道 `unit / unit_order` 到底进没进云端，
而缺了它们"按 Unit 布置"就会拿到空词单。所以仓库里带了一个一次性工具
`cloud/functions/seedwords`：**清理、导入和回查做在一起，跑一次证据一起回来**。

> **2026-10-10 换版背景**：外研四上换 2024 新版教材（10 Module → 6 Unit，
> 163 词含 8 个短语）。云端还挂着旧版 109 词的三级字段，必须先 `clean` 再
> `import`（顺序无所谓、两边都幂等，但先清后导 probe 一次就能看到干净的数字）。

1. 重新生成导入数据：`node scripts/export-words-for-cloud.js`（已跑过，见 `scripts/cloud-import/words.json`）
2. 部署它（详见第四章的 CLI 段落）：部署列表里加上 `seedwords`
3. 云开发控制台 → 云函数 → `seedwords` → **云端测试**，**第一步先清理旧版词**，参数：

```json
{ "action": "clean", "token": "wc-seed-20261008", "from": 1 }
```

> clean 按单元推进（每次扫 2 个 Unit），返回 `next_from`。**连跑 5 次**：
> `from: 1` → `3` → `5` → `7` → `9`，最后一次返回 `done: true`。
> 汇总期望：**`deleted: 80`**（旧版专加词整条删除）、**`untagged: 7`**（ECDICT
> 底库词摘"外研四上"标签退回普通词）、**`kept: 22`**（新旧教材都有的词，
> 由 import 重写字段）、`failures: []`。
> 这些数字与本地 `scripts/build-waiyan.js` 的 cleanStaleVolume 完全同构
> （tests/seed-then-assign.test.js ⑩ 已在假库验证），对不上就是云端规则跑偏了。

4. **第二步导入新词表**（分片 + 可续跑）：

```json
{ "action": "import", "token": "wc-seed-20261008", "from": 0 }
```

> ⚠️ **2026-10-09 踩坑（两次）**：云函数默认超时只有 **3 秒**，一次导完全部词会被掐断
> （实测只写进 3 条，probe 显示 `wy4a_total: 3`）。而且 `config.json` 里的
> `timeout: 60` **不会随 CLI 部署生效** —— 执行超时是函数级运行配置，只认
> 控制台「云函数 → seedwords → 配置 → 执行超时时间」的手动设置。
> 所以函数改成**分片 + 并发写入**（10 路并发，100 次 add ≈ 1 秒）：不依赖
> 任何控制台配置，3 秒内也能跑完一片。
> 用法：**连跑 5 次**，每次把上一次的 `next_from` 填进 `from`：
> `from: 0` → `100` → `200` → `300` → `400`，最后一次返回 `done: true` 即全部完成。
> 中途再被掐断也不怕：重跑即可，已完成的词会 `skipped_same` 跳过，只补缺口。
>
> 汇总期望（先 clean 后 import 的真实路径）：`added: 134`（新词入库）、
> `updated: 29`（22 个新旧教材都有的词重写三级字段 + 7 个摘过标签的词重新挂上）、
> `skipped_same: 291`（无变化的底库词跳过）、`failures: []`。

5. **第三步回查**，确认字段真的到了、旧词真的没了：

```json
{ "action": "probe", "token": "wc-seed-20261008" }
```

期望：`total: 454`、`wy4a_total: 163`、`unit_sum: 163`、**`stale_units: 0`**（换版
残留清零，非 0 就是 clean 没跑完）、每个 Unit 的 `count` 与课本一致
（28/42/27/20/26/20）、`continuous: true`（`unit_order` 是 1..n 连续）、
`top3` 是课本最前面那三个词。
`degraded: true` 只表示云端该查询走了本地排序（没建复合索引），不是失败。

6. **用完把它删掉**：控制台删除 `seedwords` 函数，并删掉本地
   `cloud/functions/seedwords/` 目录、`tests/seed-then-assign.test.js` 与
   `tests/fixtures/old-cloud-1010.js`——它能全表 upsert，留在生产等于开放一个洗库入口。

### 3.2 备选路线：控制台直接导入

1. 打开 `scripts/cloud-import/words.json`（JSON Lines 格式，**不是**标准 JSON 数组）
2. 控制台 → 数据库 → `words` 集合 → 「导入」→ 选该文件
3. 冲突处理：`insert`（首次导入）；以后更新词库用 `upsert`（依赖 word 唯一索引）
4. 导入后刷新确认条数 = 400，并随机抽查一条能看到 `volume: "wy4a"`、`unit: 3`、`unit_order: 20`

> ⚠️ **每次跑 `node scripts/build-waiyan.js`（词库三级结构变更）之后必须重跑导入**：
> 本地词库有 ≠ 云端有。忘了这一步，老师按 Unit 布置会"布置成功却是空的"。

## 四、部署云函数

微信开发者工具左侧目录树 → `cloud/functions` 下每个函数**右键 → 上传并部署：云端安装依赖**（不要选"本地安装"，Windows 本地 npm 环境各异）：

- `user`（登录）
- `task`（今日任务）
- `review`（复习反馈）
- `quiz`（出题判分）
- `class`（班级：建班/邀请码/布置任务/催学文案，批次 1）
- `check-shared`（开发辅助，可暂不部署）

**部署前必跑**：`node scripts/prepare-functions.js`——它把 `shared/`（time/srs/quiz/**wrong**）复制进每个用到的函数目录；DevTools 上传打包的是函数目录本身，缺了 `shared/` 运行时会报 `Cannot find module './shared/time'`。`npm run check` 里的 `functions:check` 会校验副本是否最新（副本已 gitignore，克隆新机器后先跑 prepare 再部署）。

### 4.0 用 CLI 部署（不用守着 GUI 点右键）

前提是 IDE 开了**服务端口**。两件必须知道的事：

- **端口不一定是你以为的那个**。它写在本机配置里，不在代码里：
  `%LOCALAPPDATA%\微信开发者工具\User Data\<hash>\WeappLocalData\localstorage_b72d….json`
  里面的 `"security":{"enableServicePort":true,"port":15717}` —— 读到几就用几，
  官方默认的 39749 只是"从没改过端口"时的值，拿它硬试会对不上。
- **CLI 不需要 IDE 的界面真的开着**：它会自己把 HTTP server 拉起来
  （输出里看到 `√ IDE server has started` 就说明通道通了）。

```bash
# 连通性自测（只读，不动云端）
"<安装目录>/cli.bat" cloud functions list --project D:/www/wordCheck \
  --env cloud1-d0gmmv8o9df84265e --port 15717

# 部署（云端装依赖）
"<安装目录>/cli.bat" cloud functions deploy --project D:/www/wordCheck \
  --env cloud1-d0gmmv8o9df84265e --port 15717 \
  --names class review seedwords task user quiz rank --remote-npm-install
```

> **已踩过的坑（2026-10-08）**：
> 1. **新函数第一次部署会报 `Creating状态，无法进行此操作`** —— 云端还在初始化，等一分钟重来一次就好，不是代码问题。
> 2. **`scripts/cloud-e2e.js` 里的 `spawnSync(shell:true)` 调 cli.bat 在某些机器上会一字不吐**（输出为空 → 脚本把所有函数判为"部署失败"）。绕法：用上面的命令手工 deploy/download，再跑 `node scripts/cloud-e2e.js --verify <下载目录>` 做回读比对。
> 3. 脚本支持 `--port 15717`，但它没法绕过第 2 条，所以这一步暂时只能手工跑。

### 4.0.1 部署后必须回读自证

把云端包下载回来跟本地比对 sha1 —— 只有这一步能证明"部署真的生效了"：

```bash
for n in class review task user quiz rank seedwords; do
  "<安装目录>/cli.bat" cloud functions download --project D:/www/wordCheck \
    --env cloud1-d0gmmv8o9df84265e --port 15717 --name $n --path .preview/cloud-verify/$n
done
node scripts/cloud-e2e.js --verify .preview/cloud-verify
```

看到 `云端=本地，v<版本戳>，依赖 N 个模块全部就位` 才算数。

### 4.1 `class` 云函数的特殊配置（2026-10-08 简报）

`cloud/functions/class/config.json` 已随代码提供，**上传部署后要在控制台确认两件事**：

1. **订阅消息权限**：云函数 → `class` → 配置 → 确保开放接口含 `subscribeMessage.send`
   （来自 config.json 的 `permissions.openapi`）。
2. **定时触发器**：`dailyBrief`，Cron `0 30 20 * * * *`（每天 20:30）。
   首次上传可能不会自动生成，去函数详情页 → 「触发管理」手动添加一遍。

配**订阅消息模板 ID**（不配就推不了，但产品不会崩——会明确回 `NO_TEMPLATE`）：

- 小程序后台 → 订阅消息 → 公共模板库选用「学习提醒」类模板，拿到模板 ID
- 把它写进 `cloud/functions/class/index.js` 的 `BRIEF.TEMPLATE_ID`
  （同一份 ID 也要写进 `miniprogram/utils/cloud.js` 的 `BRIEF_TEMPLATE_ID`，前后端必须对上）
- 模板所需字段：`thing1`（标题/作业名）、`thing2`（正文摘要）、`date3`、`time4`
- **改完必须重新部署 `class` 才生效**；改后可以云平台「云端测试」入参 `{"action":"briefSubs"}`，
  返回里 `template_ready: true` 即表示服务端已认到模板。

> 定时触发时 `event.Type === 'Timer'` 且**没有 OPENID**，代码里已专门走了这个分支；
> 如果你自己加云函数 action，别忘了开头做同样的判断，否则定时器每天夜里报错。

## 五、验证链路

1. 开发者工具编译小程序，控制台应看到 `user.login` 调用成功（app.js 启动时触发）
2. 控制台 → 数据库 → `users` 集合出现一条记录

## 六、常见错误

| 现象 | 原因与解法 |
| --- | --- |
| 调用报 `ENV_NOT_SET` | `cloud.js` 的 ENV_ID 还是占位符 |
| 调用报 `cannot find function` | 云函数没部署，或函数名拼错 |
| 报 `Env invalid` | 环境 ID 复制错了（拿成环境名 `cloud1`） |
| `task.today` 返回 0 个新词 | `words` 集合没导入或为空 |
| 重复提交计数翻倍 | `request_dedup` 集合没建 |
| 真机正常模拟器报错（或反之） | 两端身份都是 OPENID，检查工具登录的微信号是否管理员 |
| 按 Unit 布置成功但作业是空的 | 云端 `words` 还是旧导出（没有 `volume/unit` 字段）——重跑 `node scripts/export-words-for-cloud.js` 并 upsert 导入 |
| 点「订简报」提示"服务端还没配置模板 ID" | `class/index.js` 的 `BRIEF.TEMPLATE_ID` 为空，或改完没重新部署 |
| 简报一直收不到（定时器没跑） | `class` 函数的定时触发器没建；或同一天已发过（一天只发一次，手动再也点不出来是正常的） |

## 附：一键自检（看云端到底有没有数据）

云控制台 → 云函数 → `review` → **云端测试**，参数填（`all:true` 不需要小程序登录态，控制台直接能跑）：

```json
{ "action": "diagnose", "all": true }
```

返回示例与判读：

| 字段 | 含义 |
| --- | --- |
| `version` | 云函数版本戳——和最新代码对不上 = 部署没生效 |
| `stateTotal` | `user_word_state` 里的记录数（学过多少词） |
| `dirty` | **`word_id` 为空的脏记录数**——新版写入器用确定性 `_id`，脏数据已挡不住写入；`clean:true` 可顺手清掉 |
| `reviewLogTotal` | 学习明细日志总数（0 = 学习数据从未到过云端） |

清理脏数据（再填一次并执行）：

```json
{ "action": "diagnose", "all": true, "clean": true }
```

### 部署有没有生效，一眼可见

每个云函数的响应都带 `_v` 版本戳（如 `rev-20261005-state-id`）。
小程序端 Console 会打印 `[cloud] review 云端版本: xxx`；
如果打印的是 `云端是旧版本（响应没有版本戳）`，说明该函数还没重新部署。

> 学习记录在云端写入失败时，小程序会把它压进本地补传队列，
> 下次启动或回到前台自动重放（服务端按 `clientReqId` 幂等，不会重复计数）。
> 所以"临时网络问题"不会丢数据；如果 `reviewLogTotal` 长期为 0，
> 看 Console 的版本戳即可确认是不是云端还在跑旧代码。
