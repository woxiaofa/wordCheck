# 云开发部署指南（从零到家长能发任务）

> 对应 `docs/实施手册.md` 第八章批次 0~1。全程约 30 分钟，其中大半是等控制台反应。
> 前提：云环境已开通（工具「工具」菜单 → 云开发，或 tcb.cloud.tencent.com）。

## 一、填环境 ID

1. 打开云开发控制台 → 左下角「设置」→ 环境设置，复制完整环境 ID
   （形如 `cloud1-9gxxxxx123456`，不是环境名 `cloud1`）
2. 改 `miniprogram/utils/cloud.js` 第 11 行：

```javascript
var ENV_ID = 'cloud1-xxxxxxxx';   // 换成你的
```

## 二、建集合与索引

云开发控制台 → 数据库 → 「+」逐个创建集合（权限都选**仅创建者可读写**）：

| 集合 | 用途 | 本阶段必须 |
| --- | --- | --- |
| `users` | 用户 | ✅ |
| `words` | 词库 | ✅ |
| `user_word_state` | 每用户每词的 SRS 状态 | ✅ |
| `review_logs` | 复习明细 | ✅ |
| `daily_tasks` | 今日任务快照 | ✅ |
| `request_dedup` | 提交幂等去重 | ✅ |
| `quiz_sessions` / `quiz_items` | 抽查会话与逐题记录 | ✅ |
| `classes` | 班级（家长端，邀请码加入） | ✅（批次 1：class 函数） |
| `assignments` | 布置的作业 | ✅（批次 1：class 函数） |
| `word_books` / `word_examples` / `checkin_records` / `achievements` / `assignment_progress` / `orders` / `deposits` | 后续批次 | 可先不建 |

然后给已建的集合加索引（数据库 → 集合 → 索引管理 → 添加）：

| 集合 | 索引 | 类型 |
| --- | --- | --- |
| `user_word_state` | `user_id + next_review_at` | 非唯一 |
| `user_word_state` | `user_id + word_id` | **唯一** |
| `daily_tasks` | `user_id + task_date` | **唯一** |
| `review_logs` | `user_id + created_at`（倒序） | 非唯一 |
| `quiz_items` | `user_id + created_at`（倒序） | 非唯一 |
| `words` | `word` | **唯一**（防止词库重复导入） |
| `classes` | `code` | **唯一**（邀请码查班） |
| `assignments` | `class_id + created_at`（倒序） | 非唯一 |
| `users` | `class_id` | 非唯一 |

> ⚠️ 索引避坑（实测踩过）：
> 1. **索引字段是 `word`（单数）**，不是集合名 `words`——填错会导致所有记录该字段为 null，唯一索引在导入第 2 条时就报 `E11000 duplicate key`。
> 2. **索引名称在同一集合内必须唯一**，第二个索引起个新名字（如 `idx_user_word`）。
> 3. **多个字段要点「+」分行添加**（user_id 一行、word_id 一行），不要在一个框里填 `user_id + word_id`。

## 三、导入词库（300 词）

1. 生成/更新导入文件：`node scripts/export-words-for-cloud.js`
   （产出 `scripts/cloud-import/words.json`，JSON Lines 格式，**不是**标准 JSON 数组）
2. 控制台 → 数据库 → `words` 集合 → 「导入」→ 选该文件
3. 冲突处理：`insert`（首次导入）；以后更新词库用 `upsert`（依赖 word 唯一索引）
4. 导入后点集合刷新，确认条数 = 300

## 四、部署云函数

微信开发者工具左侧目录树 → `cloud/functions` 下每个函数**右键 → 上传并部署：云端安装依赖**（不要选"本地安装"，Windows 本地 npm 环境各异）：

- `user`（登录）
- `task`（今日任务）
- `review`（复习反馈）
- `quiz`（出题判分）
- `class`（班级：建班/邀请码/布置任务/催学文案，批次 1）
- `check-shared`（开发辅助，可暂不部署）

**部署前必跑**：`node scripts/prepare-functions.js`——它把 `shared/`（time/srs/quiz）复制进每个用到的函数目录；DevTools 上传打包的是函数目录本身，缺了 `shared/` 运行时会报 `Cannot find module './shared/time'`。`npm run check` 里的 `functions:check` 会校验副本是否最新（副本已 gitignore，克隆新机器后先跑 prepare 再部署）。

## 五、验证链路

1. 开发者工具编译小程序，控制台应看到 `user.login` 调用成功（app.js 启动时触发）
2. 控制台 → 数据库 → `users` 集合出现一条记录
3. 首页正常进入学习流程后，`daily_tasks` 出现今日快照，`user_word_state` 随学习产生记录
4. 云函数面板 → `task` → 云端测试，入参 `{"action":"today"}`，返回 `ok: true` 且携带 10 个新词

## 六、常见错误

| 现象 | 原因与解法 |
| --- | --- |
| 调用报 `ENV_NOT_SET` | `cloud.js` 的 ENV_ID 还是占位符 |
| 调用报 `cannot find function` | 云函数没部署，或函数名拼错 |
| 报 `Env invalid` | 环境 ID 复制错了（拿成环境名 `cloud1`） |
| `task.today` 返回 0 个新词 | `words` 集合没导入或为空 |
| 重复提交计数翻倍 | `request_dedup` 集合没建 |
| 真机正常模拟器报错（或反之） | 两端身份都是 OPENID，检查工具登录的微信号是否管理员 |

## 七、下一步（批次 1+）

## 附：一键自检（看云端到底有没有数据）

云控制台 → 云函数 → `review` → **云端测试**，参数填：

```json
{ "action": "diagnose" }
```

返回示例与判读：

| 字段 | 含义 |
| --- | --- |
| `stateTotal` | 该用户在 `user_word_state` 里的记录数（学过多少词） |
| `dirty` | **`word_id` 为空的脏记录数**——>0 会让该用户每条新词都写不进去，教练端进度恒 0 |
| `hasReviewLog` | 有没有学习明细日志（false = 学习数据从未到过云端） |
| `statsCache` | 教练端"已学 N 词"读的就是它 |

清理脏数据（再填一次并执行）：

```json
{ "action": "diagnose", "clean": true }
```

> 学习记录在云端写入失败时，小程序会把它压进本地补传队列，
> 下次启动或回到前台自动重放（服务端按 `clientReqId` 幂等，不会重复计数）。
> 所以"临时网络问题"不会丢数据；如果 `hasReviewLog` 长期为 false，
> 优先检查 `review` 云函数是不是还部署着旧版本。
