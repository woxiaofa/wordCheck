## 一、三条拒绝原因 → 对应整改

### 原因 1：「创建班级」等内容安全验证存在风险（拒绝情形 3.2）

审核原话：**必须接入内容安全 API（security.msgSecCheck），且要在小程序内任意发布的场景生效**。

整改（代码已落地）：所有「用户自由输入 → 会展示给他人」的文本，入库前全部过 `security.msgSecCheck`（v2：openid + scene + version=2）：

| 入口 | 云函数 | 检什么 | 拦下后用户看到 |
| --- | --- | --- | --- |
| 创建班级 | class `createClass` | 班级名 | 「班级名称包含平台不允许的内容，请修改后再建」 |
| 布置作业 | class `assign` | 自定义词单（逐词）+ 作业备注 | 「词单里/作业备注包含平台不允许的内容…」 |
| 改昵称 | user `profile` | 昵称 | 「昵称包含平台不允许的内容…」 |
| 换头像 | user `profile` | 图片过 `security.imgSecCheck`（≤1M 的云存储图） | 「头像图片包含平台不允许的内容…」 |

不检的输入（写清楚备查）：加入班级的**邀请码**（只做匹配，不展示不存为内容）；
**本地自定义词库**（只存本机 storage，不上传不分享）；
**拍照记词的图片**（只在本地识别，不落云存储，代码有测试锁着）；
**跟读录音**（只在内存算能量，不落盘不上传）。

判定口径：API 判违规（suggest ≠ pass / errCode 87014）→ **必拦**；
API 自身故障（权限未生效 / 网络抖动）→ 放行 + Console 记 `[seccheck]` warn，
不能让内容接口抖一下就瘫痪建班。**部署后看一眼两个函数的日志确认没有 warn**。

### 原因 2：缺「教育服务 - 教育信息展示」类目

后台操作（只有你能做）：

1. mp.weixin.qq.com → 设置 → 基本设置 → 服务类目 → 添加类目
2. 选 **教育服务 > 教育信息展示**（个人主体可选，无需办学资质）
3. 保存后重新提审时勾选该类目

### 原因 3：个人主体未开放的 UGC 记录/分享类目（建议企业主体）

审核把「创建班级 + 分享」判成了社交/笔记范畴。这是三条里最硬的一条，
整改思路是把「我们不是社区，是教育工具」讲清楚，并把 UGC 面收窄到最小：

- UGC 仅限 4 处教学输入（上表），全部已接内容安全 API —— 这正是《UGC 类小程序运营攻略》的标准整改
- 图片只有头像且过 imgSecCheck；拍照识别图片**不存储不上传**
- 录音**不落盘不上传**（口语跟读只在本机实时算）
- 分享出去的是学习统计卡片，不含任何用户创作内容

**提审时在「审核备注」里贴这段**（可直接复制）：

> 本小程序为教育工具，核心是「单词学习与老师布置词单任务」。用户输入内容仅限：
> 班级名（≤20 字）、老师录入的单词词单与作业备注（≤60 字）、用户昵称（≤20 字）与头像，
> 均为教学管理必需信息，且已全部接入微信内容安全接口 security.msgSecCheck /
> security.imgSecCheck，违规内容将在提交时被拦截。本小程序不支持评论、动态、帖子等
> 社区功能；拍照识别仅在用户本地完成，图片不上传不存储；口语跟读录音仅在本机实时
> 处理，不落盘不上传。分享出去的是学习统计卡片，不含用户创作内容。
