# 词库与发音方案 + 云开发开通攻略

> 配套 [`docs/开发与运营路线.md`](开发与运营路线.md)。本文回答三件事：
> ① 词库内容从哪来（开源 → 用户上传 → 教材词书付费的三阶段）；
> ② 发音怎么解决（有免费官方方案，也有"电脑批量生成"的开源方案）；
> ③ 微信云开发从注册到跑通的完整流程。

## 一、词库三阶段路线

### 1.1 阶段一：开源词库打底（推荐 ECDICT，MIT 协议）

**[ECDICT](https://github.com/skywind3000/ECDICT)**（skywind3000 出品）是目前最适合本项目开局的选择：

- **MIT 协议**：可商用、可修改，只需在项目里保留一份版权声明——彻底解决"释义文字有版权"的顾虑（这正是设计约定第 6 条最担心的问题）
- 约 340 万词条，**每个词自带**：音标、词性、中文释义、考试标签（中考 zk / 四级 cet4 / 六级 cet6 / 考研 ky / 雅思 ielts / 托福 toefl / GRE）、BNC + 当代语料库双重词频、柯林斯星级、牛津 3000 核心词标记、词形变换（时态/复数/比较级）
- CSV / SQLite 格式，写个 Node 脚本即可筛出第一批词书

**字段映射（ECDICT → 本项目 `words` 集合）**：

### 表 |

ECDICT 字段 | 本项目字段 | 说明
word | word | 直接用
phonetic | phonetic | 直接用
translation | def_cn | 按换行拆分，取主要义项（建议只留 1–2 条，卡片更干净）
tag | tags | zk→中考、cet4→四级、cet6→六级、ky→考研、ielts/toefl/gre 同名
frq（当代词频） | freq | 直接用（越小越常用）
exchange | variant | 拼写题的干扰项来源

**第一批词书建议**（都有现成 tag，零成本切分）：
中考词汇（zk）→ 高考词汇（zk 之外补 cet4 高频）→ 四级 → 六级 → 考研。
每本按词频升序取前 N 个，先导 3 本验证。

**⚠️ 唯一的缺口：例句。** ECDICT 没有完整例句（`detail` 字段只有少量词条有）。处理方式：
1. MVP 阶段例句非必需（学习卡正面是词 + 音标，释义在背面；抽查的选义题用释义本身）；
2. 扩充时用 AI 辅助生成初稿 + 人工抽检（每词 1 句、用词在该词目标难度内），**自撰例句没有版权问题**；
3. 例句放独立的 `word_examples` 集合按需加载（实施手册 4.1 已预留）。

### 1.2 阶段二：用户上传词单（txt / Excel / PDF / 拍照）

**核心设计决定：用户上传的只是"单词列表"，不是释义。** 释义和音标由系统自动从 ECDICT 导入的词库匹配——这样：
- 解析逻辑简单（只需要认出"哪些是英文单词"）；
- **完全绕开释义版权问题**（用户传的词表本身不受版权保护）；
- 生僻词匹配不到时提示"该词暂未收录"，引导用户反馈。

**架构与实现路径**：

```
小程序端                    云端
选文件/拍照                云存储（存原始文件）
  │ wx.cloud.uploadFile ──→  fileID
  └──────────────────────→ 云函数 import-words：
                              txt   → 按行/逗号/空格切分，正则提取 [a-zA-Z-]+
                              Excel → xlsx 库（云函数装依赖后上传）
                              PDF   → pdf-parse 库提取文本后同 txt
                              拍照  → OCR 得到文本后同 txt
                            匹配 words 集合 → 建词书 → 存 word_books
```

- **拍照 OCR 两个选择**：① 微信官方 OCR 插件（在后台"服务市场"搜 OCR，个人主体可用，有免费额度）；② 腾讯云 OCR API（更准，按次付费约 ¥1/千次以内）。识别对象是打印体英文单词，难度低，①就够。
- **解析器优先级：txt 先行**（粘贴文本框 + 上传 .txt，一天就能上线），Excel 第二，PDF/拍照最后——真实使用中"老师发个 txt/截图"是主流。
- **合规**：用户上传内容必须过 `msgSecCheck`（内容安全接口），词书名默认私有。
- 上传文件大小控制在 5MB 内，超出提示拆分。

### 1.3 阶段三：按年级 / 按教材词书（付费）

这是最自然的付费点，但**版权是最硬的约束**，按风险从低到高排：

1. **考试大纲词表（中考/高考/四六级/考研）**：ECDICT 已覆盖，风险最低 → 免费或低价，作为获客面
2. **自建分级词书**（如"小学 800 / 初中 1600 / 高中 3500"）：教学大纲词汇量是公开事实，用 ECDICT 按词频 + 标签组合切出来 → **可作为第一批付费词书**
3. **教材单元同步词表**（人教 PEP、外研社等"Unit 1 学这些词"）：**这是出版社的核心资产，直接照搬有实质风险**。三条合规路径：
   - 与一线教师共建（老师提供自己整理的授课词单，收益分成——顺便就是教练端冷启动的钩子）
   - 只做"学期进度"不做"单元同步"（粒度粗一点，但只用大纲词，安全）
   - 规模化后谈正式授权
4. **付费模式建议**：基础词书全免费；"教材同步 + 老师定制 + 押金班配套"打包进教练端订阅，不做单卖——词书单卖的付费意愿太弱，bundled 进服务才有溢价

## 二、发音方案

### 2.1 三个方案对比

### 表 |

方案 | 成本 | 音质 | 依赖 | 适合
**A. 微信同声传译插件（WechatSI）** | 免费（有免费额度，可申请提升） | 中上，可接受 | 在线、官方维护 | **MVP 首选**
**B. 电脑批量生成 → 云存储**（开源 TTS 如 [Piper](https://github.com/rhasspy/piper)） | 一次性电费 | 高（神经网络人声） | 离线生成、上线后零外部依赖 | 规模化、听写题
**C. 腾讯云 TTS API** | 按字符计费 | 高 | 在线、按量付费 | 备选（B 的云上版）

**"直接电脑读"= 方案 B，完全可行**：在你的电脑上用 Piper（开源、离线、免费商用）把整本词书的每个词批量合成 mp3，一次跑完几百上千个词，然后统一上传云存储、把 fileID 写进 `words.audio_file_id`。这正是实施手册里"预生成音频放云存储"的落地方式，而且音质比系统 TTS 好、没有第三方链接失效风险。

### 2.2 推荐路线（结合本项目代码）

- **现在（MVP / 内测）→ 方案 A**：零部署、零成本、几行代码。改造点就在 `pages/study/study.js` 的 `speakWord`（当前的 `audioUrlFor` 空桩就是为它留的）。
- **规模化（听写题上线前）→ 方案 B**：听写题的发音是"考试材料"，对清晰度要求高于学习卡，值得上批量生成。

### 2.3 方案 A 接入步骤（WechatSI，约 10 分钟）

1. 登录 [微信公众平台](https://mp.weixin.qq.com) → 设置 → 第三方设置 → 插件管理 → 添加插件 → 搜索"同声传译"（AppID `wx069ba97219f66d99`，认准提供商"腾讯"）→ 添加并授权，即时生效
2. `app.json` 增加声明：

```json
"plugins": {
  "WechatSI": { "version": "0.3.6", "provider": "wx069ba97219f66d99" }
}
```

3. 替换 `speakWord` 实现：

```javascript
var plugin = requirePlugin('WechatSI');

speakWord: function (w) {
  var self = this;
  plugin.textToSpeech({
    lang: 'en_US',
    tts: true,
    content: w.word,
    success: function (res) {
      var ctx = wx.createInnerAudioContext();
      ctx.src = res.filename;          // 返回临时音频文件路径
      ctx.play();
      ctx.onError(function () { wx.showToast({ title: '读音播放失败', icon: 'none' }); });
    },
    fail: function () {
      wx.showToast({ title: '朗读失败，请稍后重试', icon: 'none' });
    }
  });
}
```

注意事项：每次播放前 `stop()` 上一个 InnerAudioContext（否则连点会叠音）；真机才生效，开发者工具里可能无声。

### 2.4 方案 B 操作摘要（Piper 批量生成）

1. 电脑装 Piper（Windows 有预编译包），选一个英文女声/男声模型（如 `en_US-amy-medium`）
2. 从数据库导出词表 → 脚本逐词生成 `word.mp3`（几 GB 以内的量，家用电脑一晚跑完）
3. 微信开发者工具 → 云开发控制台 → 存储 → 批量上传（或写脚本走云存储 API）
4. 把 fileID 批量写回 `words.audio_file_id`（一个数据库更新脚本）
5. `audioUrlFor` 改为返回 fileID，`InnerAudioContext` 直接支持云文件协议

## 三、微信云开发开通攻略（从零到本项目跑通）

> 前提澄清：**个人主体就能开通云开发**（收钱才需要企业主体，云开发本身不需要）。以下全程不需要服务器、域名、备案。

### 3.1 注册与准备（约 30 分钟）

1. **注册小程序**：[mp.weixin.qq.com](https://mp.weixin.qq.com) → 立即注册 → 选"小程序" → 一个未注册过公众平台的邮箱 → 主体选**个人**（够用；以后要上支付再注册企业主体或做主体变更）→ 按流程实名
2. 拿到 **AppID**：登录后台 → 开发 → 开发管理 → 开发设置 → AppID（AppSecret 暂时用不到，云开发不需要）
3. **下载微信开发者工具**：[官方下载页](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html) → 选 Windows 稳定版

### 3.2 开通云开发环境（约 10 分钟 + 认证等待）

**当前费用模式（2026 年起按"资源点"计，务必知道）**：

### 表 |

套餐 | 价格 | 资源点 | 说明
免费体验版 | ¥0 | 3,000 点/月 | 需在购买页用兑换码领取；**小程序正式发布后第 15 天到期**，之后必须转付费，适合开发期
个人版 | ¥19.9/月 | 40,000 点/月 | 独立开发者/小型线上项目，**MVP 上线就选它**
标准版 | ¥199/月 | 330,000 点/月 | 用户量起来再说

（1,000 资源点 ≈ ¥1；超出套餐按资源包/按量付费。粗略参照：日活百人级的学习类小程序，个人版通常够用。）

**操作**：
1. 开发者工具打开 wordCheck 项目（导入根目录，认 `project.config.json`）→ 把 `project.config.json` 里的 `appid` 换成你的
2. 点工具栏**"云开发"**按钮 → 开通 → 按引导创建环境
3. **建议建两个环境**：`dev`（开发造数据）和 `prod`（线上），免费额度只有一个环境，那就先建 `dev`，上线前再开正式的
4. 创建完成后，控制台顶部能看到**环境 ID**（形如 `xxx-1a2b3c`）→ 填进 `miniprogram/utils/cloud.js` 的 `ENV_ID`

### 3.3 建数据库集合与索引（约 20 分钟）

云开发控制台 → 数据库 → 逐个创建集合（清单见实施手册 4.1，MVP 最少建这 5 个）：

`users`、`words`、`user_word_state`、`review_logs`、`daily_tasks`

**索引同样在控制台里点**（每个集合 → 索引管理，MVP 必建 3 个）：

- `user_word_state`：`(user_id 升序, next_review_at 升序)` —— 查"今日到期词"的生命线
- `user_word_state`：`(user_id, word_id)` **唯一** —— 防止同一词两条状态
- `daily_tasks`：`(user_id, task_date)` **唯一** —— 任务快照幂等

### 3.4 部署云函数（约 10 分钟）

1. `cloud/functions/` 下每个目录是一个函数。先部署已有的两个：
   右键 `review` 目录 → **上传并部署：云端安装依赖**；同样处理 `quiz`
2. （待开发）`user`、`task` 函数写好后同样方式部署
3. 云开发控制台 → 云函数 → 能看到函数列表和调用日志，部署成功与否一目了然

### 3.5 验证跑通（检查清单）

- [ ] 编译小程序无报错，首页正常显示"今天的任务"
- [ ] 学习页：手势可用（此时仍走本地词库，正常）
- [ ] 控制台 → 云函数 → `review` 的调用日志有记录（说明 `ENV_ID` 配对了）
- [ ] 控制台 → 数据库 → `user_word_state` 开始有数据写入
- [ ] 真机预览：手机扫码，学习 + 抽查全流程走通

### 3.6 与本项目路线的衔接

对照 [`开发与运营路线.md`](开发与运营路线.md)：
- 本攻略完成 = **阶段 1 的基础设施部分**（环境 + 集合 + 部署）
- 剩下的阶段 1 工作：`user` / `task` 云函数开发、ECDICT 词库导入（写一个筛选脚本生成 JSON → 控制台导入或脚本写入）、发音接入（上文方案 A）
- **顺序建议**：内测（阶段 0，用本地版）与云开发开通**并行**——注册和环境的等待期不阻塞测试

## 四、一句话总结

1. **词库**：ECDICT（MIT）打底切考试词书 → 用户上传只传"词表"、释义系统自动匹配 → 教材词书做付费但走"老师共建"避开版权
2. **发音**：MVP 用微信同声传译插件（免费、10 分钟接入）；听写题上线前用 Piper 在电脑上批量生成 mp3 传云存储
3. **云开发**：个人主体即可开通；开发期用免费体验版（注意上线后 15 天必须转付费），上线选个人版 ¥19.9/月
