# 小程序注册信息填写指南

> 适用于本项目（背单词 / 后续扩展为全科任务抽查）。
> 写这份文档的原因：注册时填的**名称、主体、类目**三件事，事后改的成本都远高于现在多花十分钟想一想。
> 文中规则均已核对微信官方客服文档与开放社区 2026 年现行口径，具体以 MP 后台实时提示为准。

---

## 〇、结论先行（5 条）

1. **个人主体能收钱了，但有条件。** 2026 年 8 月 31 日起，微信向个人主体开放**虚拟支付**：个人持身份证 + 服务类目含「工具」+ 个人认证 30 元/年 + 已备案，即可在小程序内销售虚拟商品，月限额 10 万。**本项目所有付费点（付费词库、教练端订阅、拍照额度）都是虚拟商品，完全够用。** → 详见第四节。
2. **个人主体仍然不能升级成企业/个体工商户。** 官方口径："小程序不支持个人主体直接变更为企业主体认证"。但有了虚拟支付，"必须换号"不再紧迫——**等月流水接近 10 万、或机构客户要发票时再换不迟**。
3. **名字建议一次取全科通用的。** 个人主体改名**每个自然年只有 2 次**，用完只能等明年。改名后还要在 **7 日内变更备案**。
4. **搜索流量不用靠名字。** 名称不带"单词"会损失一部分搜索量，但可以在简介里写清楚（简介同样参与搜索匹配），代价远小于以后改名。
5. **全科能做，但 K12 学科培训是资质红线**，定位必须保持「记忆/复习/自查工具」。详见第六节。

> ⚠️ 一个连锁反应：**虚拟支付要求类目含「工具」**。所以个人主体的类目就选「工具 → 效率工具」，不要为了"听起来像教育"去选教育类目（个人主体选教育类目还需教师资格证，且可能失去虚拟支付资格）。

## 一、先做主体决策（这比取名字重要）

### 1.1 两种主体的能力对比

| 能力 | 个人主体 | 个体工商户 / 企业 |
| --- | --- | --- |
| 注册成本 | 0，当天可用 | 个体户约几百元（多地线上可办，1–3 天） |
| **卖虚拟商品**（会员/付费内容/额度） | ✅ **虚拟支付**（30 元/年认证，月限额 10 万，见第四节） | ✅ 虚拟支付 |
| **普通微信支付**（实物、线下、扫码） | ❌ 需商户号，个人拿不到 | ✅（需营业执照 + 对公账户） |
| **给机构开增值税发票** | ❌ 只能税务代开，B 端客户通常不接受 | ✅ |
| 微信认证 | ✅ 30 元/年（个人） | ✅ 300 元/年 |
| 改名 | 每年 2 次，用完等明年 | 每年 2 次，用完可付费认证重置 |
| 改名后备案 | 7 日内必须变更 | 同 |
| 服务类目 | 工具/生活服务等窄范围 | 全类目（含教育、电商等，需对应资质） |
| 获取手机号 | ❌ | ✅ |
| UnionID 打通 | ❌ | ✅ |
| 流量主广告 | ❌（需企业认证） | ✅ |
| 投放广告 | ❌ | ✅ |

### 1.2 三条路，按你的情况选

**方案 A（推荐，本项目的最优解）**
直接用**个人主体**注册 → 类目选「工具 → 效率工具」→ 做 30 元/年的个人认证 → 备案 → 开通虚拟支付。
**先把内测跑起来收第一笔钱，全程零注册成本。** 等出现下面三个信号之一再考虑办个体户/公司：
- 月流水接近 10 万（虚拟支付天花板）
- 有机构/学校要批量采购并**要发票**（个人主体开不了专票，这是 B 端真痛点）
- 需要普通微信支付（卖实物、线下收款）

*理由：本项目付费点全是虚拟商品，虚拟支付完全覆盖。办公司这件事可以往后推到"真的需要"时再办，而不是现在。*

**方案 B（一步到位）**
先办**个体工商户营业执照**（全程网办、费用几百元，1–3 天下证）→ 用个体户主体注册小程序。
*适合：你确定很快要做 B 端机构客户、或想尽早开企业认证拿全部能力。代价是现在多花几百元和几天时间。*

**方案 C（保守）**
只做免费工具。个人主体够用，付费功能全部不做。

> **换号预警（三个方案都要知道）**：个人主体不能变更为企业主体。将来真的要换号，流程是：注册新号 → 旧号改名腾出名字（一年 2 次够用）→ 7 日内变更备案 → 新号过审后引导用户迁移 → 并行一段时间再下线旧号。**所以现在取一个通用名（如「每日抽查」），换号时能直接沿用，省掉这次折腾。**

> **我的建议**：你前面已经明确规划了教练端付费、押金、付费词库，那**商业化的概率很高**。如果办个体户对你来说不是难事，走方案 A；如果暂时不想办，走方案 B 但**现在就把名字取成通用的**（第五节会说明为什么这对换号也有好处）。

## 二、命名规则（改名前必读，数字都是硬的）

| 规则 | 具体 |
| --- | --- |
| 长度 | 4–30 个字符，**1 个汉字 = 2 字符**（即 2–15 个汉字） |
| 简称 | 从名称中按顺序截取，4–10 字符（2–5 个汉字），展示在任务栏 |
| 唯一性 | 微信公众平台内唯一；**同一主体下可与自己的公众号同名**；不同主体不得与已存在的公众号/小程序同名 |
| 个人主体禁用 | 公司、集团、中心、官方、网、平台等企业性质字样 |
| 慎用（触发保护词审核） | 教育、培训、学院、学校——命中后需额外审核（约 7 个工作日），个人主体风险更高 |
| 改名次数 | 境内主体每自然年 **2 次**（1 月 1 日重置）；个人主体用完等明年，企业主体可付费认证重置 |
| 改名后 | **7 日内**到【账号设置 → 小程序备案 → 变更】提交变更备案 |
| 其他 | 审核通过后不可撤销；不得含连续 2 个以上特殊符号 |

**提交前务必在 MP 后台实时检测名称占用情况，并准备 2–3 个备选**（短词大概率已被占用）。

## 四、收款：个人主体也能收钱了（虚拟支付）

> 2026 年 8 月 31 日落地，微信官方文档已上线「虚拟支付：个人」章节。
> **验证方式**：登录 MP 后台看【支付与交易 → 虚拟支付】有没有入口，有就是已开通。

> **2026-10-05 后台实测**：【支付与交易 → 虚拟支付】入口可见，但三项条件均未满足——
> ① 主体类型为已认证的小程序（当前：**未认证**）→ 点「前往认证」，个人认证 30 元/年；
> ② 小程序类目符合要求（显示要求：**企业 事业单位**）→ 这是当前页面展示的通道条件；
>    先把类目设为「工具 → 效率工具」并完成认证后观察此条是否刷新；若认证后仍锁"企业 事业单位"，
>    说明个人虚拟支付通道尚未对该账号开放，届时再核实开通方式（不要为此急着换主体）；
> ③ 小程序主体信息完备（当前：**缺陷**）→ 去【设置 → 基础设置】补全主体信息后此条会变绿。
> 顺序：**补全主体信息 → 类目设为工具 → 30 元认证 → 回来看虚拟支付条件**。

### 4.1 规则速览

| 项目 | 规则 |
| --- | --- |
| 主体 | 个人（持中国大陆居民身份证） |
| **类目** | **服务类目必须包含「工具」** |
| 前置条件 | 完成小程序认证（个人 **30 元/年**）+ 已完成 ICP 备案 |
| 月收款限额 | **10 万元** |
| 费率 | Android 约 1%；iOS 12%（Apple IAP 苹果税） |
| 结算 | Android T+3 可提现；iOS 约 45–60 天 |
| 退款 | Android 后台主动退；**iOS 无法主动退款**，用户向 App Store 申请 |
| 接口 | `wx.requestVirtualPayment`（与需商户号的 `wx.requestPayment` 是两套系统） |

开通后拿到三个关键值：**AppID、OfferID（支付账号）、现网 AppKey（支付密钥）**。

### 4.2 对本项目的意义（重要）

本项目的付费点**全部是虚拟商品**，虚拟支付能完整覆盖：

| 付费点（见 `docs/角色体系与商业模式.md`） | 能否用虚拟支付 |
| --- | --- |
| 付费词库 / 教材同步词书 | ✅ |
| 教练端订阅（按活跃学员） | ✅ |
| 拍照上传额度包 | ✅ |
| 口语练习次数包 | ✅ |
| **押金 / 打卡对赌** | 🟡 见下方提醒 |

**三个必须提前算清楚的账：**

1. **iOS 抽成 12% 且结算慢 45–60 天。** 定价时要把苹果税算进去；如果目标用户以安卓为主影响不大。
2. **iOS 端不能主动退款。** 押金模式依赖"达标退款"，在 iOS 上你要么走 Android 专属、要么把押金改成"达标解锁下一期权益"（不退款，也就没有退款诉求）。**这基本决定了押金模式要么只做安卓、要么改形态。**
3. **个人主体开不了增值税发票。** 家长个人付费无所谓；但**机构/学校批量采购、老师报销**通常要专票——这是将来办个体户/公司的真实触发点，不是"赚到 10 万"才触发。

### 4.3 什么时候仍然必须办个体户/公司

- 月流水接近 10 万（天花板）
- **B 端客户要发票**（最常见、来得最早）
- 需要普通微信支付：卖实物、线下扫码收款
- 想投放广告、开流量主（都需企业认证）

### 4.4 关于 OPC（一人公司）与国家补贴

OPC = One Person Company（一人公司）。工信部《人工智能中小企业创业支持计划（2026—2028 年）》明确鼓励"一人公司、超级个体"，各地人社/园区配套了真金白银：

- 云南：符合条件的 OPC 创业者 **5000 元一次性创业补贴**
- 重庆：最高 **8000 元一次性创业补贴** + 1–5 万"创业启航资金" + 创业担保贷款（个人最高 50 万，50% 贴息）
- 北京石景山：认定人才 **10 万创业启动资金**、算力补贴年度最高 200 万
- 南京江宁麒麟科创园：新注册 OPC 企业 5 万启动奖励、最高 30 万/年算力券

**但要泼一盆冷水：**
- 这些政策**主要面向人工智能领域的 OPC**（以 AI 为核心生产力），本项目是教育工具，能否认定要看当地口径
- 多数补贴绑定**特定园区入驻、特定人群**（毕业五年内高校毕业生等）和**本地社保/纳税**
- 补贴是"锦上添花"，**不要为了拿补贴去注册公司**——先有收入再谈补贴

**建议顺序**：个人主体 + 虚拟支付先跑通收款（零成本、当天可开）→ 真有稳定收入且需要发票/B 端客户时，再注册个体户或公司（此时顺带查本地 OPC 与创业补贴政策，能拿就拿）。

### 4.3 服务类目（决定能调用哪些 API、能否过审）

**个人主体 —— 推荐：**

```
工具 → 效率工具
```

**理由**：个人主体可选类目很窄，"教育 → 在线教育"需要提供**个人教师资格证或与持证机构的合作证明**，拿不出来就会被驳回。背单词本质是记忆工具，选"工具-效率"最稳，且不影响卡片、发音、云开发等全部功能。

## 六、以后做"全科 + 家长老师发任务"：能做吗？

### 5.1 技术上：完全可以，而且成本不高

现在的数据是 `words`（word / phonetic / pos / def_cn / example_en / example_cn），要做全科只需两步抽象：

1. **把"词"抽象成"条目 item"**：加 `subject` 字段（english / chinese / math / …），条目内容从"单词+释义"扩展为"题干+答案+可选提示"。
2. **题型从"三种"扩展为"题型工厂"**：现在的选义 / 拼写 / 听写已经是按题型分发的（见 `shared/quiz.js` 的 `planTypes`），古诗填空、公式默写可以复用同一套"出题—作答—判分—回流 SRS"的骨架。

`utils/books.js` 的词书机制已经是可扩展雏形，将来"词书"变"科目-教材-单元"三级即可。

**建议：现在不要提前重构。** 理由是所有科目共用的那条 SRS 主链路还没被真实用户验证过，先拿英语跑通、确认留存能起来，再花两天抽象一次更划算。

### 5.2 合规上：这是真正的红线，不是技术问题

| 要做的事 | 风险 | 说明 |
| --- | --- | --- |
| 单词/古诗/公式的**记忆与自查工具** | 🟢 低 | 工具属性，名称与简介保持"工具"定位 |
| 家长给孩子布置**复习任务** | 🟡 中 | 家庭场景，属自用，风险可控 |
| 老师给学员布置**作业并收费** | 🟠 中高 | 接近"校外培训"，需教育类目资质，**个人主体不可能拿到** |
| K12 学科**在线培训 / 在线授课 / 辅导** | 🔴 高 | 需办学许可等资质，"双减"后审核极严，个人主体直接不可做 |

**三条具体建议：**

1. **定位永远写"工具"，不写"培训/辅导/课程"。** 名称、简介、页面文案、给审核员的说明都保持一致。产品做的是"记忆与自查"，不是"教学"。
2. **收费对象是教练/家长的能力，不是学科内容本身。** 收费点放在"布置任务、查看数据、管理多个学员"这些**效率功能**上，而不是"买语文课/数学课"。这既是之前商业模式文档里"配额制"的思路，也降低了合规风险。
3. **个人主体下不要做 UGC 分享。** 用户上传词表、教练自定义任务属于用户生成内容，个人主体审核更严，必须过 `msgSecCheck` 内容安全检测。内测期建议只做本地自用，等企业主体再开放分享。

### 5.3 换号时的名字衔接（如果走方案 B）

个人号占着的名字要先腾出来给新号：
1. 用个人号的 2 次改名机会，把它改成一个临时名（如"每日抽查旧版"）
2. 立刻（7 日内）提交变更备案
3. 旧名释放后（改名后旧名有保护期，同主体 2 天、其他主体约 30 天），用个体户新号注册同名
4. 新号过审后，在个人号内引导用户迁移，跑一段时间再注销个人号

> 这就是为什么**现在取通用名很重要**：通用名在你换号时同样适用，省掉一次改名和一次备案变更。
