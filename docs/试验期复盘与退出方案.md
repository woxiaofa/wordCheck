### 4.1 静态本地版改造 —— ⚠️ 有一个必须先澄清的认知偏差

**「把小程序改成纯静态本地版挂网上」这句话里有个技术矛盾：微信小程序不能挂到网页上访问。**
可能的实现路径只有三条，代价差别很大，需要用户先选：

| 方案 | 是什么 | 成本 | 代价 |
|---|---|---|---|
| **A. 小程序本地版**（推荐，最快） | 保留小程序，把 `utils/cloud.js` 换成 localStorage 适配器，去掉 `wx.cloud.init`，删 `cloudfunctionRoot` | ~半天 | 班级/派作业/催学/报告分享全部作废，退化成**单人离线背单词**；仍需提审发布才能被人用到 |
| **B. H5 静态版挂 GitHub Pages**（"挂网上"的正解） | 把已有的 `单词抽查demo.html`（95KB 单文件原型）扩成完整 H5，词库+进度走 localStorage | ~2~3 天 | 失去微信入口和 OPENID；但**真正 0 成本、可被搜索引擎收录、链接可随便发** |
| **C. A + B 都做** | 小程序留作壳，H5 作主阵地 | ~3~4 天 | 两套 UI 要维护 |

**改造的技术面很干净**（这是好消息）：全项目只有两个文件碰云 —— `miniprogram/utils/cloud.js` 和 `miniprogram/utils/profile.js`（`grep -rl "wx.cloud" miniprogram/` 只命中这 2 个）。业务规则全在 `shared/`，不动。所以 A 方案本质是写一个同签名的本地 shim。
