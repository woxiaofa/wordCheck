# 角色体系、入口分流与商业模式

> 本文是《可行性与产品方案》第十四章（商业化）与第十一章（教练端）的**落地版修订**，
> 针对已确定的新定位：**自然流量默认学生 → 免费自用 → 引入第三方（家长/老师/教练）→ 付费**。
> 文中所有金额与转化率均为【待验证假设】，合规结论已联网核实（见每节标注）。

---

## 一、结论先行

1. **默认角色 = 自学者（learner），且第一屏绝不弹"请选择你的身份"。** 新用户打开就该看到词库并开始背，
   任何前置选择都是流失点。角色是**用出来的，不是选出来的**。
2. **角色升级入口：小程序内条件触发为主，分享卡片是真正的获客主渠道，
   订阅消息只做服务通知、绝不做邀请。**（这是你问的那个问题，理由见第三节，共 5 条，其中第 1 条是合规红线）
3. **"成为家长"和"成为老师"是两件完全不同的事，不能用同一个入口。**
   家长靠**学生邀请**（学生自己没动机升级，但他有动机"让爸妈看到我"）；
   老师/教练靠**主动申请 + 轻审核**（他们有明确的工作动机，会自己来找）。
4. **商业模式的一句话：学生端免费不是慈善，是漏斗顶部；钱发生在"第三方被引入"之后。**
   背单词本身免费竞品做得更好，用户不会为"我能背单词"付费，但家长会为"知道孩子背了没有"付费、
   老师会为"不用自己出题判卷"付费。所以**角色升级链路 = 变现链路**，它是产品里最该打磨的一段。
5. **首月免费必须给足额度（建议 5–10 席），只给 1 席等于没给。** 理由见 5.3。

## 二、角色模型

### 2.1 三类角色（不要拆太细）

| 角色 | 标识 | 谁 | 核心诉求 | 付费动机 |
|---|---|---|---|---|
| 自学者 | `learner` | 自然流量进来的所有人（默认） | 把词背下来、别忘 | 弱（免费竞品够用） |
| 家长 | `parent` | 孩子的监护人 | 看到孩子的真实进度 | 中强（焦虑驱动） |
| 教练 | `coach` | 老师、培训机构教练、托管班 | 布置任务不费劲、能看到谁没做 | 强（省下的是工作时间） |

**早期不要把"老师"和"教练"拆成两个角色。** 两者在产品上做的是同一件事（对一群人布置任务 + 看完成度），
拆开只会多一套 UI 和一套权限判断。等到确实出现"机构版"需求时再拆。

### 2.2 关键决策：角色是叠加的，不是切换的

一个用户可以同时是 `learner` + `coach`（老师自己也在背单词；家长也可能自己想学）。
因此**不做"身份切换器"**，而是：

- 小程序主界面永远是"我的学习"（learner 视图），这是所有人的默认落点；
- 教练/家长视图从「我的」页的一个卡片进入，入口只在绑定/申请成功后才出现；
- 数据不割裂：`user_word_state` 永远跟着 `user_id` 走，不跟着角色走。

**理由**：互斥角色会带来两个真实麻烦——① 用户每次进来都要切一次，摩擦累积成流失；
② 一个人两个身份的学习数据会被拆成两份，SRS 排程直接错乱。

### 2.3 角色获取的两条路径

| 路径 | 适用 | 触发方式 | 预期占比 |
|---|---|---|---|
| **A · 被邀请**（主） | 家长 | 学生生成邀请卡 → 微信转发给家长 → 家长点开即绑定 | 高 |
| **B · 主动申请**（次） | 教练/老师 | 小程序内入口 → 填 3 个字段 → 轻审核 → 开通 | 中 |
| **C · 定向入口**（运营用） | 两者 | 运营给种子老师发带参二维码/落地页 | 冷启动期主要靠它 |

**路径 A 和 B 的入口形态完全不同**，这是本节最重要的结论，详见第三节。

## 三、申请入口放小程序内还是推送消息里？（核心问题分析）

### 3.1 三个渠道对比

| 维度 | 小程序内条件触发 | 订阅消息推送 | 分享卡片 / 带参二维码 |
|---|---|---|---|
| 合规风险 | 无 | **高**（见 3.2 第 1 条） | 无 |
| 能否抓住"动机峰值时刻" | ✅ 能（刚背完/刚打卡/刚出周报） | ❌ 不能（异步、脱离场景） | ✅ 能（由用户主动发起） |
| 转化链路长度 | 1 步（看到即点） | 4 步（推送→点开→找入口→申请） | 1 步（点开即落地页） |
| 是否消耗稀缺资源 | 否 | **是**（一次授权一条） | 否 |
| 打扰感 | 可控（不出现就不存在） | 不可逆（发出即打扰） | 由真人发起，不算打扰 |
| 面向"邀请家长" | 🟡 入口是学生的，但动作是分享 | ❌ | ✅ 天然就是它 |
| 面向"申请成为教练" | ✅ 最合适 | ❌ | 🟡 可用于定向招募 |

### 3.2 结论：订阅消息不要用在这件事上（5 条理由）

**第 1 条（决定性的，是红线）：微信对订阅消息的定位是"服务通知"，不是营销通道。**
已核实的规则：一次性订阅需用户主动授权且一次授权对应一条；长期订阅仅限政务/医疗/交通/金融/**教育**等类目，
且需行业资质与非个人主体审核。更重要的是——**推送内容必须与用户订阅时的场景对应，
拿业务授权发营销内容（折扣、活动预热、功能推广）会导致用户投诉，投诉累积会影响账号的消息能力**。

"你用了 3 天了，要不要升级成家长/老师？"——这就是一条推广内容，不是服务通知。
用户点"投诉"的概率不低，而**消息能力被限制 = 整个提醒体系报废**，代价远大于那点转化。
（【已核实】规则方向成立；【待核实】教育类目长期订阅的具体资质要求，需在小程序的实际类目下确认。）

**第 2 条（经济）：订阅额度是稀缺资源，要用在真正能提高留存的地方。**
一次性订阅一次授权一条，是"攒币"模型——你每请求一次授权，用户就消耗一次耐心。
真正值得发的只有三条：

1. 教练布置了新任务（**这条价值最高**，因为它带"有人等着看"的压力）
2. 今日任务还没做（学生自己订阅的，用于自己督促自己）
3. 本周周报已生成（家长/教练订阅，天然的付费触点）

把这三条的额度拿去发"邀请你升级"，是把最贵的资源用在最不确定的事上。

**第 3 条（时机）：角色升级的动机峰值出现在"刚产出成果"之后，而推送抓不住这个时刻。**
学生连续打卡 7 天、刚学完一轮、刚生成第一份周报——这三刻是他最愿意"给人看"的时候。
小程序内可以在结算页当场挂一个按钮；推送是异步的，发到的时候用户早就不在那个情绪里了。

**第 4 条（链路）：推送 → 点击 → 打开 → 找到入口 → 申请，四步，每步掉一半。**
小程序内是"看到就点"，一步。

**第 5 条（不可逆）：推送发出去就收不回。** 对还没建立信任的新用户推一条"要不要当教练"，
第一印象成本很高。小程序内的入口错了可以撤，且用户没看到就等于不存在。

### 3.3 订阅消息唯一应该出现在这条链路上的位置

不是"邀请升级"，而是**用户已发起动作之后的服务通知**：

- 学生生成了邀请卡但 24 小时没人接受 → 「你分享的邀请还没有人加入，要再发一次吗？」
- 家长接受了邀请但孩子还没绑定 → 「还差一步：让孩子确认一下」
- 教练布置了任务 → 「XX 老师给你布置了 15 个词，今天 20:00 前完成」

这三条都符合"用户先做了某个动作，系统告知该动作的结果/进展"，合规且有用。

### 3.4 小程序内入口的具体触发规则

**展示条件（全部满足才出现）：**

- 累计完成 ≥ 3 轮学习 **或** 连续打卡 ≥ 3 天
- 且当前未绑定任何 coach / parent
- 且用户没有手动关闭过（关闭后 30 天内不再主动出现，但「我的」页保留一个低权重常驻入口）

**出现时机（按效果排序）：**

1. 学完一轮的**结算页**（动机最强，且此刻用户有成就感）
2. 连续打卡 ≥3 天时的**首页任务卡下方**
3. 生成第一份**周报之后**

### 3.5 文案：不要说"申请成为家长"

**学生对"升级角色"这件事零动机。** 他不会想"我要变成家长"，他会想"我背了 7 天，想让人知道"。
所以文案必须换主语：

| 场景 | ❌ 不要这样写 | ✅ 这样写 |
|---|---|---|
| 邀请家长 | 申请成为家长 | **「让爸妈看到你的进步」** → 生成一张邀请卡，发给家长 |
| 邀请家长 | 绑定家长账号 | **「家长能看到：今天背了几个、错了哪些、连续几天」**（说清家长看到什么，降低学生的顾虑） |
| 申请教练 | 升级为教练 | **「你是老师吗？可以布置任务给学生」** + 副文案「系统自动判分，你只看谁没做」 |

**第三个判断（反直觉但重要）：真正会主动申请的是老师/教练，不是家长。**
老师有明确的工作动机（省下出题和判卷的时间），他会自己来找入口；
家长没有，家长是被孩子的成果带进来的。**所以这两条链路的产品形态必须不同**——

- **家长 = 邀请制**：学生端生成卡片 → 微信转发 → 家长点开 → 一键接受（不需要填任何东西）
- **教练 = 申请制**：小程序内入口 → 填 3 个字段（身份/科目/大致学生数）→ 轻审核 → 开通
  （审核在早期可以做成"秒过"，只留字段用于后续分层运营；等到有人滥用再收紧）

## 四、特殊入口：带参分享与绑定关系

### 4.1 参数要用短码，不要直接塞 JSON

**技术约束（已核实）：**

- 小程序码（`getwxacodeunlimit`）的 `scene` **最大 32 个可见字符**，只支持数字、大小写英文和少数符号，
  不支持 `%`（中文无法 urlencode），也不能带参数在 `page` 里。
- 普通转发卡片的 `path` 可以带 query，最大 128 字节，宽松得多。

**因此统一走短码反查：**

```
invites(code, type, creator_id, role_to, class_id, book_id,
        expire_at, max_use, used_count, created_at)
```

- 小程序码：`scene = "i" + 8 位短码`（如 `i7Kq2mXp`）
- 转发卡片：`path = "pages/join/index?invite=7Kq2mXp"`
- 两者都反查同一张 `invites` 表，拿到完整上下文

短码用 8 位 base62（约 62^8 种），不自增、不暴露业务量。

### 4.2 三条分享链路

| # | 谁分享给谁 | 卡片内容 | 学生落地页 |
|---|---|---|---|
| 1 | 教练 → 学生（布置任务后） | 「XX 老师给你们布置了 15 个词 · 今天 20:00 截止」 | 显示任务内容 + 「接受任务」 |
| 2 | 学生 → 家长 | 「我连续打卡 3 天了，你要不要看看我错了哪些词」 | 家长看到孩子的进度（只读） |
| 3 | 教练 → 家长（班级码） | 「XX 班的家长请加入，可查看孩子每日任务完成情况」 | 绑定孩子 |

**链路 1 的落地页必须在 3 秒内说清三件事**：谁布置的、要做什么、什么时候截止。
这类"任务驱动的冷启动"留存远高于"自己选词库"——因为用户没有"我要不要开始"的决策成本。

### 4.3 绑定关系与总量保护

```
relations(id, coach_id, student_id, kind[parent|coach],
          status[pending|active|ended], source, created_at, accepted_at)
```

- **必须双向确认**：教练发邀请 → 学生点"接受"才算绑定（`pending → active`）。
  否则任何人扫到码就能看到别人的学习数据。
- **一个学生可以被多个角色绑定**（家长 + 老师），但要有**总量保护**：
  今日教练任务总量上限（建议：不超过系统任务的 50%，且绝对值 ≤ 20 词/天），
  超出的自动顺延到明天，并在教练端提示"该学员今日任务已满，已顺延"。
  **没有这个保护，两个老师同时布置任务会把学生压垮，然后学生和教练一起流失。**

## 五、免费 / 付费边界：用配额，不用功能开关

### 5.1 为什么是配额而不是开关

"免费/付费"如果做成功能开关（这个功能免费用户不能用），免费用户会在第一次撞墙时流失。
做成**配额**（这个功能每月能用 N 次）则不同：用户先体验到价值，用完才遇到墙，转化率显著更高，
且可以根据成本灵活调整 N。拍照（OCR）、口语评测这类**我们真的要花钱**的功能尤其适合配额制。

### 5.2 学生（自学者）侧

| 能力 | 免费 | 付费 | 说明 |
|---|---|---|---|
| 默认词库（3–5 本：中考/高考/四级/六级/考研按考试 tag 切） | ✅ 完整 | — | 见《词库与发音方案》阶段一 |
| 精品 / 教材同步词库 | ❌ | 单本购买 or 会员内 | 版权成本真实，见《词库与发音方案》阶段三 |
| 系统提醒（今日任务 / 周报） | ✅ | — | 受订阅消息额度限制（见 3.2） |
| SRS 复习、错词本、抽查判分 | ✅ 完整 | — | 核心永远免费，这是获客的根本 |
| txt / Excel 上传自己的词表 | ✅ 每月 N 次（建议 5） | 超出后 | 解析成本≈0，给足额度换口碑 |
| **拍照上传** | ❌ | **打包进会员，不要按次卖** | 见下方说明 |
| **口语练习 / 发音评测** | ❌ | **按次包**（如 9.9 元/50 次） | 语音评测 API 按次计费，成本真实且比其他项高一个量级 |
| 周报简版 / 详细版 + 成长曲线 | 简版 | 会员 | 沿用第十四章：付费只买"证据与便利" |
| 押金打卡挑战 | 见 5.4 | — | 只面向坚持 4 周以上的成年人 |

**关于拍照上传，我的建议和你的设想不同：不要单独按次收费。**

理由是行为层面的：拍照对**老师**是刚需（拍课本单词表上传），对学生是弱需求。
一旦按次收费，老师每次掏手机拍照都会犹豫一次，直接压低这个功能的使用率；
而"布置自己的词表"恰恰是教练端留存的命脉。
**正确做法：把拍照打包进教练订阅（如"每月 100 次拍照额度"），让教练放心用；**
对纯自学者则作为会员权益。成本可控（OCR 单价很低，且额度有上限），收益是留存。

### 5.3 教练 / 家长侧（对你方案的修正建议）

你的原方案：新教练首月免费 + 免费 1 个学员；内测用户永久免费 1 个学员；付费内容后期付费。
方向完全对，我建议三处调整：

**① "免费 1 席"要永久 + 完整（内测用户的那 1 席尤其不能阉割）。**
内测用户是你最便宜、最可信的口碑渠道。给他一个残缺的 1 席，他不会替你传播；
给他一个完整的 1 席（任务布置、数据看板、催学文本全开），他才会说"这东西真好用"。
成本上，一个活跃学员的云成本约 1–2 元/月，完全负担得起。

**② 首月免费必须给足额度（建议 5–10 席），只给 1 席等于没给。** ← 这是本节最关键的修正
首月免费的目的是让教练体验"带一个班"的价值感。只给 1 席的话，
他感受到的是"我用一个小程序管一个学生"——这件事他自己用微信就能做，产品价值为零。
**给 5–10 席，他才会第一次体验到"一眼看到 8 个孩子谁没做"的爽感。**
到期后回落到 1 席 + 付费墙——**这个从 8 掉回 1 的落差，才是真正的转化触发点。**

**③ 按"活跃学员"计费，不按"绑定学员"。**
绑定 40 人但只用了 12 人，就按 12 人算。理由有二：
- 降低心理成本（教练不用担心"多绑一个人就多花钱"）；
- 更重要的是**避免教练为了省钱踢人**——踢人这个动作对产品的伤害极大，
  它会让被踢的学生的学习记录失去教练侧上下文，且制造负面情绪。
按活跃计费，教练会愿意多绑、多试，这正是我们要的。

**建议档位（数字待 A/B 验证）：**

| 档位 | 席位数（月活跃学员） | 价格 | 权益 |
|---|---|---|---|
| 免费（永久） | 1 | 0 | 完整权益（不阉割） |
| 新教练首月 | 10 | 0 | 完整权益（到期回落至 1 席） |
| 小班 | 10 | 29 元/月 | + 拍照额度 100 次/月 + 自动周报 |
| 标准班 | 30 | 69 元/月 | 班级规模天然是 30–50，**主推档** |
| 机构 | 100 | 149 元/月 | + 多教练协作 |
| 学期卡 | 按档 | 4 个月打包（约 3.3 个月价） | 老师按学期付费，9 月开学是付费高峰 |

### 5.4 押金模式：保留个人版，但优先做"班级挑战"

个人押金沿用第十四章设计（30/50 两档、只面向已坚持 4 周的成年人、达标全额返还、
未达标转为下月会员余额、金额上限 99、单独记账），这里不重复。

**新增一个我认为更值得先做的变体：教练发起的「班级打卡挑战」。**

教练发起"30 天打卡挑战"，家长/学员**自愿**押 30 元，到期达标全额退。它比个人押金好在三点：

1. **合规叙事更自然**：押金的对象是"参与一个班级活动"，而不是"个人对赌"，
   退款条件（到课 ≥24 天）客观可核验，纠纷概率低；
2. **教练有动力组织**：这是教练端罕见的"能制造话题"的功能，
   教练组织一次挑战 = 一次免费的续费理由（也可以给他留一个"组织费"分成位）；
3. **完成率显著更高**：社交压力 + 群体进度可见，比一个人默默对赌有效得多。

合规红线不变：**仅限成年人（微信实名）、金额上限 99 元、押金单独记账不进经营账户、
绝不做"不达标就归平台"的写法**。拿不到合规路径就直接砍掉，押金是锦上添花不是支柱。

> ⚠️ **2026-08 新增的技术约束**（见 `docs/小程序注册与命名指南.md` 第四节）：
> 个人主体走**虚拟支付**时，**iOS 端开发者无法主动退款**（只能用户向 App Store 申请，
> 文档涉及 80 天时限）。押金模式依赖"达标退款"，所以只有三条路：
> ① 押金只做 Android；② 改成"达标解锁下一期权益"（不退款，也就没有退款诉求）；
> ③ 等有了企业主体和普通商户号再做。**建议直接选 ②，形态更简单也不用分端。**

### 5.5 上线顺序（不要同时上）

## 六、数据驱动的任务推荐（教练端的核心差异化）

### 6.1 v1 是规则，不是 AI

不要一上来做"智能推荐"。三套规则就能覆盖 90% 的场景，且可解释（老师不信黑箱）：

| 候选包 | 内容来源 | 适用场景 |
|---|---|---|
| **班级共性错词 TOP 10** | `select word_id, count(distinct user_id) from quiz_items where class_id=? and is_correct=false group by word_id order by 2 desc` | 常规复习。**这是教练端唯一无法被纯算法替代的价值**——一个孩子错是偶然，五个孩子错同一个词就该集体讲 |
| **课本进度包** | 教练指定教材 + 单元 → 词表 | 同步教学 |
| **个人薄弱包** | 每个学员自己的 `stage` 低 + 到期词 | 分层作业 |

### 6.2 分层任务：同一个班，不同内容

同一个班布置任务时，按每个学员的掌握度自动调整配比：

- 错词多 / 掌握率低的学员：**70% 复习 + 30% 新词**
- 掌握好的学员：**30% 复习 + 70% 新词**

这就是"AI 替代不了老师"的那个部分的产品化——老师本来就会这么做，
只是他没时间给 40 个孩子各出一份。系统替他做，他只负责确认。

### 6.3 关键交互：推荐是「可编辑的草稿」，不是一键发送

**教练的价值感来自"我做了判断"。** 如果系统一键自动发完，教练会觉得"那还要我干什么"，
续费理由就没了。所以交互必须是：

```
系统给出 3 个候选包（含每个包的理由，如"这 10 个词上周班里有 6 个人答错"）
   ↓ 教练点选一个
   ↓ 预览（可增删词、改题量、改截止时间、选发给谁）
   ↓ 编辑（可选）
   ↓ 发送
```

**一定要显示"为什么推荐这些词"。** 老师不信黑箱，但信"班里有 6 个人错了这个词"。

### 6.4 发送后的闭环

布置 → 学生端多一张**教练任务卡**（对应 13.1 的 `assignments`，**不要混进今日任务**，
因为教练任务的压力来自"有人看见完成度"，混进去就失去了这个性质）
→ 完成度实时回传 → 教练看板按完成度排序 → **一键催学生成文本 → 复制粘微信群**。

催学必须做成"生成文本 + 复制"，不能做成"自动推送"（理由见 10.2 与 3.2 第 1 条）。

## 七、数据结构补充（在第十三章基础上新增）

```js
// 邀请 / 分享短码
invites(code, type, creator_id, role_to, class_id, book_id,
        expire_at, max_use, used_count, created_at)

// 绑定关系（双向确认）
relations(id, coach_id, student_id, kind[parent|coach],
          status[pending|active|ended], source, created_at, accepted_at)

// 配额（免费额度、首月额度、拍照次数、席位数统一走这一张）
entitlements(id, user_id, kind[seats|upload_txt|upload_photo|speech|report],
             quota, used, period[month|forever], expire_at, source[trial|paid|beta])

// 订阅
subscriptions(id, user_id, plan, status, start_at, end_at, seats, source)

// 押金挑战（班级版）
deposit_challenges(id, creator_id, class_id, amount, start_at, end_at, target_days)
deposit_joins(id, challenge_id, user_id, amount, status, joined_at, result_at)
```

`users` 表的 `role` 字段改为**数组** `roles: ['learner', 'coach']`（叠加而非互斥，见 2.2）。

## 九、待验证假设清单

| 假设 | 怎么验 | 判据 |
|---|---|---|
| 自学者会主动邀请家长 | 阶段 1 看邀请卡生成率与家长接受率 | **生成率 <5% → 说明学生没这个动机，改从教练侧冷启动** |
| 首月 10 席能提升教练付费转化 | 对比"首月 1 席"与"首月 10 席"两组 | 看次月留存付费率差值 |
| 教育类目能申请到长期订阅 | 在真实类目下申请"作业提醒"模板 | **拿不到 → 提醒只能靠一次性订阅攒额度，教练任务提醒要重写** |
| 学生对"被布置任务"的接受度 | 看带参落地页的接受率与次日留存 | 接受率 <40% → 落地页文案或任务量有问题 |
| 拍照打包进订阅 vs 按次卖 | A/B | 看功能使用频次与续费率 |
| 班级挑战的参与率 | 看自愿押金的参与比例 | <15% → 说明教练没动力组织，退回个人押金 |
