# 口语跟读与 AI 纠音 · 分期方案（第 1 期已实现）

**日期**：2026-11-08 · **项目**：功课抽查（个人主体小程序 + 微信云开发）
**来源**：用户与一位真实英语老师交流得到的痛点 —— 书面作业好查、听力作业很多工具能看到「学没学」，
只有**开口读**最难查：孩子每天把语音发到老师微信，老师要逐条点开听，极其费时间；
老师认为「AI 听纠音」会有很大市场。

> 文档里用「作业」描述业务背景；**对外文案与提审说明一律用「跟读练习 / 本机回放 / 自查标注」**，
> 不出现课程、培训、教学、报名、付费、批改、打分、评测等词（见第 6 节）。

## 1. 先摆清楚的产品判断

老师的时间黑洞其实是两块：

| | 内容 | 要不要 AI |
|---|---|---|
| ① | **收作业、统计谁交了、逐条点开听**（搬运成本） | 不需要 |
| ② | **判断念得对不对**（专业判断） | 需要 |

AI 纠音只解决 ②，但 ① 不需要 AI 就能省掉大半时间，而且能立刻验证「这位老师到底会不会真用」。
`docs/竞品分析与建议.md:139-143` 早就把「AI 跟读打分」列为 **P2 · 先别做**，理由正是
录音上传 + 评分 API + 存储 + 儿童语音合规 + 个人主体审核风险，并建议「先用零成本方案验证需求：
跟读录音 → 回放给孩子自己听 / 发给家长听，看有多少人真的用。有人用再上自动打分」。
**本轮分期与该建议完全一致。**

### 用户已拍板的 6 个决定

1. 分期，**先零 AI 闭环**；2. **只备份、暂不续费**（第 1 期零云端）；
3. 跟读材料**词级 + 自定义文本两者都要**；4. AI 阶段**先做选型对比**、不锁供应商；
5. 第 1 期**纯本地闭环**、不做老师端汇总；6. 全库备份列为 P0。

### 必须知情的三个代价

- **第 1 期不解决老师的收作业痛点**：无后端、无汇总表、无上传，只验证「孩子会不会真的录、家长愿不愿听」。
- **不续费**：按 `docs/试验期复盘与退出方案.md:123`，班级 / 派作业 / 催学 / 报告分享会全部作废，
  退化成单人离线背单词。不只是新功能没底座。
- **备份没做**：工作日志 2026-10-24.md:70 明写 `exportall`「尚未部署到云端」，
  下载目录与项目目录均无导出 JSON。文档推算 ≈11-10 数据释放不可恢复。「暂时没看到报错」是宽限期表现。

## 2. 第 1 期：零 AI 口语闭环（本轮已实现）

### 2.1 闭环

```
选词 / 粘贴跟读口令 → 听词级示范音 → 录音 → 本机回放自听
   → 重录 / 标记已读 / 家长确认 → 生成文字汇总 → 家长主动复制转发
```

- **只转发文字汇总，不转发录音**：录音是本机 `USER_DATA_PATH` 文件，跨设备路径不可达，
  硬发过去只会是个别人打不开的死链。
- 汇总字段：日期范围 / 录音条数 / 独立天数 / 回放数 / 已读数 / 家长确认数 / 词级 vs 自定义占比。
- 老师端异常清单、只看低分条目 —— **第 2 期才有**。

| `miniprogram/utils/oral.js` | 本机索引 CRUD / 12 条淘汰 / 录音状态机 / `saveFile` 持久化 / 汇总文字 |

### 2.3 数据模型（`oral_records`，只在本机）

`STORAGE_KEY = 'oral_records'` · `MAX_RECORDS = 12`（对齐 `drafts.js`），淘汰最老并 `unlink` 删文件。

```
id / client_record_id   同一值；后者是第 2 期接回服务端时的幂等唯一键
type                    'word' | 'custom'
ref_text / ref_word     要读的文本、词级时的词
code_id                 口令时间戳，用于区分材料来源
audio_path / duration_ms / file_size / created_at
listened / marked_read / passed
source                  'local'
```

**绝不写** `user_word_state_v2` / `activity_log` / `checkin.js`：那些是「按天词数 ≥16 算完成」的口径，
混进录音次数会污染 SRS 排程、掌握率、quiz 选题、皮肤解锁判定和简报统计。
`tests/oral-store.test.js ⑧` 直接扫源码禁止这些字面量出现。

### 2.4 录音采集

| 参数 | 值 | 理由 |
|---|---|---|
| 格式 | mp3 / 16kHz / 单声道 / 48kbps | 60s ≈ 360KB；与第 2 期 16k 评测输入对齐，免重采样 |
| 时长 | 上限 60s，到点自动收尾 | 防忘按停止、防文件过大 |
| 持久化 | `onStop` → `saveFile` 到 `USER_DATA_PATH` → 写索引 | 临时路径当晚会失效 |
| 单例 | 一个 `RecorderManager` + 一个 `InnerAudioContext` | 防回调串台、防叠音 |

状态机 `IDLE → RECORDING → SAVING → IDLE`（回放为并行 `PLAYING`）。
起录时**同步占住 `RECORDING`**：授权是异步的，若等 `.then` 才设状态，空窗里重复点击会漏进来、
页面也来不及把按钮切成「录好了，停」。`onHide` / `onUnload` 调 `cancelRecord()` 自动收尾保存。
`onError` **不吞错**，分类成授权拒绝 / 来电中断 / 编码失败 / 空间不足，由页面给人话提示。

### 2.5 示范音与自定义文本

- **词级**：复用 454 个本地 Piper mp3 与 `tts.speak()` 的第 ① 级，`tts.js` 一行未改。
- **自定义文本没有句子级示范音**（词库无音素/音节字段、无句子级音频；`docs/上线检查清单.md:105`
  禁止引入教材课文原文）。零云端解法：按空格/标点拆词 → 命中本地清单的渲染成可点 `word-chip`
  逐词点听，未命中置灰只显示文本。
- **只把清单里有的词交给 `tts.speak()`**：清单外的词会触发它的云端兜底，而这版承诺不联网、
  且云端能力随时可能失效。`oral.speak()` 先过 `hasLocal()` 再放行。

### 2.6 老师给的文本怎么到学生手里（无云端）

**主路径：剪贴板「跟读口令」短码**，格式 `WC1.<base64(紧凑JSON)>.<4位校验和>`，
紧凑 JSON 只有 `{v, t, ref, n, ts}` 五个字段。约束：整条 ≤600 字符、`ref` ≤200 字符、
**只放英文**（中文经 base64 膨胀且说明另发）、字段白名单（丢弃未知字段，防夹带姓名/手机号）、
`n` 与实际词数一致性校验、解码失败给「口令不完整 / 版本不支持」等人话提示。

复制走 `privacy.copy()`、读剪贴板走 `privacy.paste()`，两者都在 `privacy.js` 单点。
辅路径：`onShareAppMessage` 带 `?code=`，免复制粘贴但长度受限。
第三种「同机自定义朗读本」最稳但跨设备不成立，本期不做。

### 2.7 包体取舍：为什么是独立分包 `pkg-oral`

原方案打算把新页放进 `pkg-media`，实测撞了硬约束：该分包已有 454 个音频（1878KB），
加上四个页面文件后到 **2059KB > 2048KB 上限**，`verify-project.js` 当场拦下。
所以拆出独立的 `pkg-oral` 分包（14KB），`pkg-media` 回到 2044KB。

顺手把 `scripts/verify-project.js` 的体积校验从「写死只统计 pkg-media」改成
**按 `app.json.subpackages` 逐个统计**，否则新分包会成为检查盲区，主包体积也会算错。
主包 547KB、新页不放主包（`launch.test.js ⑦` 锁死真实页 ≤5 个，当前正好用满）。

> 注意：`pkg-media` 余量一度只剩约 4KB；2.8 节删掉退役的独立抽查页后回到约 22KB。
> 以后要加音频或页面，仍要先估算体积，别再往里塞。

### 2.8 接入背词主流程（2026-11-08 追加，用户拍板）

> ⚠️ **本节是 2026-11-08 的历史方案，已于 2026-11-13 整体删除**
> （旧第 0 步闸门、独立「开口读」页与首页入口都不再存在，见第 9 节）。
> 以下仅保留当时的决策过程供追溯。

用户真机反馈「没看到口语相关的」，随后拍板：

> 不管之前口语做到哪里了，点击【开始背单词】第一轮就先验口语，
> 之后再按之前的听看选择，和后面拼写等。

**做法**：在 `drill` 页加一个**第 0 步「开口读」**，走完（或跳过）才进原来的
`recog（认）→ spell（写）→ loop（巩固）`。顺序由 `begin()` / `afterOral()` 编排，
`phase` 状态机与 `endRound()` 的三行序列一个字没改 —— 40+ 条 `drill-flow` 断言因此不用返工。

| 决策 | 理由 |
|---|---|
| 用 `?oral=1` 显式开关，不默认全开 | ① 班级作业 / 教练试做等入口保持原流程；② `drill-flow` / `offline-assign` 的测试桩 `onLoad({})` 仍是纯背词 |
| 只挂在 `onLoad`，不挂 `onAgain()` | 「第一轮」= 每次进入页面读一遍；「再来一轮」不该把孩子又踢回去 |
| 口语关不进 `phase`，只用一个 `state: 'oral'` | 认/写/巩固的轮次、进度条、题型全不动，改动面收敛在 1 个 js + 1 个 wxml |
| 必给「这次先不读，直接开始」出口 | 麦克风授权在儿童设备上被拒是常态；`goStudy` 是 `redirectTo`，没有返回键可退，卡住等于背不了单词 |
| 一轮只录 1 条 | `MAX_RECORDS=12`，逐词录 10 条会把历史录音挤爆 |

**「验口语」的诚实边界**：第 1 期零 AI，这一关只能做到「听标准音 → 开口念 → 可选录一条回放自听」，
**不判断念得对不对**。老师那句「不知道他念得对不对」要等第 2 期接评测 API 才能回答。
对外文案不要说成「口语打分 / 纠音」。

**不碰的东西**：`utils/oral.js` 与 `privacy.js` 一行没改（录音仍走唯一入口 `oral.start()`）；
口语关不写 `activity_log` / `checkin.js`，不是另一项打卡；不往 `user_word_state_v2` 写伪状态。

**包体连带处理**：新增口语关代码把 `pkg-media` 顶到 2051KB（自设 2MB 红线）。
借这一步把上一轮已确认「整个流程里都没用」的独立抽查页 `pkg-media/pages/quiz/` 删除
（24.7KB），`study` 页的「开始抽查」引导改指背词页，包体回到 2026KB。
`utils/quiz.js` 出题模块与 `cloud/functions/quiz` 云函数**保留**，仍被 `drill` 与各云函数使用。

**验证**：新增 `tests/oral-gate.test.js` 9 项并登记进 `check` 链；7 组变异全部被抓住
（去掉开关 / 跳过口语关 / 卡住跳过出口 / 之后进写而非认 / 偷偷写打卡 / 删 wxml 跳过 / 底栏忘剥 query）。

## 3. 隐私与合规

- `app.json` 保留 `__usePrivacyCheck__: true`。按微信现行规则，`permission` 用于位置类，
  `scope.record` 靠 **mp 后台隐私指引勾「麦克风」+ 代码里 `wx.getSetting`/`wx.authorize`** 保证，
  不往 `permission` 里塞。**此项按当时官方规则复核**，若真机/审核实际要求再补并同步改断言。
- mp 后台 → 设置 → 服务内容声明 → 用户隐私保护指引：现有四项（剪贴板 / 相册写入 / 相册读取 /
  摄像头）之外**补勾「麦克风」**，用途写「跟读录音，供本机回放自听与家长在本机收听」，
  保存期限写「仅存用户设备本机、最多 12 条、可手动一键清空、卸载即清理、不上传服务器、不向第三方共享」。
- `privacy.onDenied(err, scene)` 三档：`clipboard / microphone / album`，旧签名 `onDenied(err)`
  仍按剪贴板处理（6 处既有调用不用改）。`ensureRecord()` 处理「曾拒绝过授权」的分支 ——
  此时 `wx.authorize` 不会再弹，必须走 `wx.openSetting`，否则就是永远点了没反应。
- **儿童语音第 1 期不出端**，合规压力低；但隐私指引仍须写全，否则线上录音按钮静默失败、
  审核判「功能不完整」。
- **提审口径红线**：保持「工具」类目与「记忆 / 复习 / 自查工具」定位。功能描述用
  「跟读录音、本机回放、自查标注、家长本机收听」；**禁用**课程 / 培训 / 教学 / 报名 / 付费 /
  充值 / VIP / 辅导班 / 批改 / 打分 / 评分 / AI 评测。
- 个人主体 + `docs/备案材料.md:77` 已对外承诺「不提供任何付费服务」+ 首页挂「不开放付费」→
  `docs/角色体系与商业模式.md:220` 曾规划的「9.9 元/50 次按次包」**当前不可行**，API 成本只能自担。

### 把试验期判定线坐实

`docs/试验期复盘与退出方案.md:94,98` 的判定线是「**或**」：拿到 ≥1 条非外研四上词库/朗读文本需求

**老师这次只说了「有市场」，不等于「我这个班愿意试用」** —— 第 1 期的核心任务之一就是坐实信号。

给这位老师看一个「零后端、不上传、可当场演示」的本机 demo：录一句 → 回放 → 标记已读 →
口令微信往返 → 汇总文字复制转发。不问账号、不传数据。

零云端可观测信号（全部来自本机索引 + 人工回收）：录音条数 / 独立天数、回放率、标记已读率、
词级 vs 自定义占比、口令导入次数、汇总卡片转发次数；
「愿意整班试用」的明确表态靠首页/设置页/跟读页的客服入口人工回收。

**进第 2 期门槛**：硬门槛 ≥1 位老师明确「我这个班可以用」或 ≥1 条非外研四上词库需求；
软信号 ≥3 个家庭连续 ≥7 天录音、回放率 ≥50%、标记已读率 ≥40%、汇总卡片被转发 ≥1 次。
只有「口头有市场」而无人实试用 → 不接 AI。

## 5. 第 2 期：AI 打分选型（只设计，未开发）

| 维度 | 腾讯云智聆 SOE | 讯飞 ISE | ASR + 文本比对 |
|---|---|---|---|
| 粒度 | **音素级 + 词/句级**，含 `PronAccuracy` / `PhoneInfos` / `MatchTag`（漏读错读） | 音节级，多维度，**按儿童/成人差异化打分** | 仅文本完整度（漏读/多读/词序），**给不出发音准确度** |
| 生态 | 与云开发同源，账号/账单可复用 | 需新开讯飞账号、新密钥、自建中转 | 需新接 ASR |
| 接入 | 服务端 SDK / WebSocket 流式；**不用小程序插件版**（密钥放端上有风险） | WebAPI + 服务端中转 | 接口简单，但分词/归一化/编辑距离/儿童容错全自研 |
| 成本 | 基础版预付费约 9.9 元/1 万次、后付费约 0.005 元/次（2026-07 文档，**需复核**） | 个人认证免费额度 + 套餐约 60 元/万次起（口径不同，**需核实**） | 一句话识别约 3.2 元/千次（**免费额度需核实**） |
| 儿童语音 | 出端 | 出端 | 出端 |
| 匹配「只看异常清单」 | **高**：音素 + `MatchTag` 可直接聚合低分清单 | 高（儿童场景略优），成本更高 | **低**：读错但 ASR 猜对时完全测不出 → 不满足核心诉求 |

## 8. 体验主流程落地：口语从「闸门」变成「题型」（2026-11-12）

## 10. 真机反馈第二轮：授权卡死、息屏死键、跳过无响应、判定误伤（2026-11-13）

用户跑 1.1.44 后反馈六点，逐条落地：

| 反馈 | 根因 | 做法 |
|---|---|---|
| 提示里有「点击开始 / 再点击结束」，但没这个功能 | 上一版为模拟器留了点按开关（`onTapHold`），真机上和按住手势互相干扰，纯属噪音 | 删除两个 `onTapHold` 入口与对应文案；只保留按住手势 |
