背单词教练小程序：可行性与产品方案

文档版本：v1.0　　文档性质：可行性分析 + 产品需求（合一）
适用范围：决策层快速拍板 + 工程师据以开工。本文件不含任何未标注来源的市场数据。

一、结论先行

1.1 三句话结论

  1. 能做，但不该做成"又一个背单词 App"。背单词工具本身是红海：免费竞品功能完整、词书齐全、用户迁移成本几乎为零。单纯做一个"界面更好看的词表 + 复习计划"，大概率死于无人使用。
  2. 真正可能成立的是"抽查与督促"这件事本身。你在招聘平台看到的"背单词教练 / 单词速记 / 抽查督促"岗位，说明市场上有人愿意为"有人盯着我（或我的孩子）背完"付钱。这件事的价值不在词库，而在闭环：布置任务 → 用户执行 → 被抽查 → 结果被第三方看见 → 产生压力。
  3. 因此建议的形态是"免费工具 + 付费监督服务"，而不是"付费工具"。工具负责零成本获客和留存，付费点放在"抽查报告、真人教练、家长可见进度"上。这样即使工具部分被免费竞品打平，赚钱的那一环仍然存在。

1.2 最便宜的可证伪实验（先做这个，再决定写不写代码）

不要一上来就开发。花 1 周时间用手工方式验证需求真假：在微信群/朋友圈找 5–10 位 K12 家长，用现成词表 + 每晚固定时间在群里发 10 个词的默写题并逐个批改，收 9.9 元/周（或免费试用一周后报价）。

判据：

  • 若 ≥3 位家长愿意付费或持续交作业超过 7 天 → 需求真实，值得投入开发，且你已经知道家长到底为什么付钱（是"批改"还是"有人催"）。
  • 若家长只在你免费时才交作业、一提钱就消失 → 说明需求是"免费的焦虑缓解"，此时应该转向 B 端（卖给已经收费的单词速记机构/教练做工具），而不是做 C 端 App。
  • 若家长连免费都不交作业 → 需求不成立或你的触达渠道不对，停止。

这个实验的成本约等于你的时间，却能把后面最贵的风险（做出来没人用）提前暴露。

1.3 本节置信度

结论部分基于产品逻辑推演与你的需求信号，不是市场测量结果。已验证：仅"招聘平台存在相关岗位"这一事实由你提供。

二、本文档的读法与置信度标记

为避免把推测当事实，本文档每个章节末尾标注置信度：

  • 【已验证】：可在本机或公开渠道直接确认的事实。
  • 【用户观察】：由你提供的一手观察，未经我独立核实。
  • 【待验证假设】：合理但未证实的推断，使用前需先核实。全文所有未经核实的数字都会带此标记。

关于本次编写的一个重要限制，必须说明：本次编写环境无法联网核查竞品定价与市场数据（搜索引擎结果页返回的是无意义内容，检索接口不可用）。因此本文档刻意不写任何竞品价格、市场规模、增长率、留存率的具体数值。取而代之的是一份"你需要去核实什么、去哪核实、核实结果如何影响决策"的清单（见第三章）。这是文档的诚实边界，不是遗漏。

三、需求信号与待验证清单

3.1 我们手上唯一的原始信号

【用户观察】招聘平台上存在"背单词教练 / 单词速记 / 抽查督促"类岗位。

这个信号的价值在于它的方向性：企业不会长期为一个没有付费方愿意买单的岗位发工资。但它不足以支撑决策，因为它不能回答三个关键问题：

  1. 这些岗位是B 端机构内部岗（机构收家长的钱、雇人执行），还是C 端自由教练（个人接单）？
  2. 付费方是家长还是成人学习者本人？
  3. 这个市场是在增长还是在被免费 App + AI 替代而萎缩？

不同答案会导向完全不同的产品：若是机构内部岗 → 做 B 端管理工具（帮一个教练同时盯 50 个学生）；若是自由教练接单 → 做教练的个人接单与交付工具；若是家长直购 → 做 C 端家长端产品。

3.2 待验证清单（建议 1–2 天内完成，成本极低）

核实项去哪查结论如何影响决策
B 端 vs C 端招聘 JD 原文（读职责描述里是否提到"带班""学员群""机构名"）、面试或电话询 HR 时的三句话决定做 B 端工具还是 C 端产品，这是最上游的分叉
真实报价直接问一个正在做这行的教练/机构：接多少个学生、每人每月多少钱、每周投入多少小时决定毛利模型是否成立；这是竞品定价最可靠的来源，比任何榜单都准
竞品功能与定价各大应用商店的背单词 App、微信里搜索"背单词"小程序、竞品付费页判断你的差异化点是否已被覆盖；重点看它们有没有"抽查"和"成果外显给第三方"
需求是否增长招聘岗位数量随时间变化、家长社群的讨论热度决定投入规模：增长 → 可以做产品；萎缩 → 只做服务不投入研发
平台约束微信官方文档：小程序类目资质、订阅消息规则、虚拟支付限制直接决定"提醒推送"和"收费"能不能按设想实现（见第十二章）

【待验证假设】以上各项在本文档中均按"未知"处理，未代入任何具体数值。

3.3 本节置信度

【待验证假设】除 3.1 的需求信号外，全部内容为待核实项。

四、用户与场景

4.1 三类人群与付费动机

人群谁付钱动机强度核心痛点优先级
K12 家长（小学高年级至高中）家长强（焦虑驱动、愿意为"确定感"付费）孩子不主动、自己不会教/没时间盯、看不到进度P0
考研 / 四六级 / 专升本学生本人中（有明确目标，但自驱易断）缺监督、错词反复忘、计划执行不下去P1
成人英语补基础本人弱偏中（付费能力有，优先级低）时间碎片、无考试压力、容易放弃P2

关键洞察：K12 场景里"用的人"和"付钱的人"不是同一个人。这带来两个产品要求：① 学生端体验必须轻、快、不讨厌（否则学生抗拒 → 家长放弃）；② 家长端必须能"看到东西"（否则家长感觉钱白花）。任何只做学生端、不把成果外显给家长的设计，在这个市场上都收不到钱。

4.2 典型场景

场景时长用户状态产品该做什么
通勤/课间碎片3–10 分钟单手操作、随时被打断只推"复习到期词"，单手可完成，中断可续
睡前固定时段15–25 分钟安静、可专注推新词 + 完整复习，允许"多学一点"的弹性
教练/家长抽查5 分钟第三方视角、要结论不要过程生成"能不能过"的结论页 + 错词清单
考前突击30–60 分钟高压、要即时回报按高频词优先排序、进度条可视化、允许暂停 SRS 规则

4.3 场景设计里最容易犯的错

把"提醒"当成"督促"。真正的督促包含三要素：明确的截止时间、被第三方检查、检查结果有后果。只发一条"该背单词了"的推送，三要素一个都不占，效果约等于零。产品设计必须围绕这三要素构建，这也是第九章"数据看板"里"可转发周报"存在的原因——它负责"被第三方检查"。

4.4 本节置信度

【待验证假设】人群划分与动机强弱来自常识推演；K12 家长的付费意愿强弱必须在 3.2 的核实中确认。

五、竞品形态与差异化

5.1 竞品不是"另一个背单词 App"，而是四类形态

形态拿走了什么价值留下的空档
大型背单词 App（含 AI 规划类）词库全、算法成熟、体验好、多为免费完全不知道用户"是否真的会拼写"；没有任何社交压力；成果不外显
微信小程序类背单词小工具免安装、易分享功能浅、无沉淀数据、普遍无抽查闭环
真人陪学/督学服务真人盯、有温度、可定制贵、不可规模化、质量依赖个人、交付过程无沉淀
线下单词速记班强约束、有同伴环境、家长熟悉贵、受时间地点限制、效果难持续

空档在于交集："有抽查闭环 + 成果可外显 + 价格接近免费工具"三者同时满足的产品很少。免费 App 不做抽查（因为抽查需要判定对错，成本更高且体验更"重"）；真人服务有抽查但贵且不标准化。

5.2 差异化只押三个点

  1. 真·抽查，不是"自测"。关键差异在"交卷制"：一次 10 题全部答完才出结果（见 7.1）。即时判分是练习，交卷判分是考试，考试才有压力。
  2. 错词精准回流。错过的词在次日、第 3 天、第 7 天强制再出现，并且出题方式换一种（选义错过的，下次用拼写考）。这是留存和口碑的来源："它真的记得我不会什么。"
  3. 成果外显。一张可以直接转发给家长的周报卡：本周学了几个词、掌握率、错词 TOP10、连续打卡天数。这张卡是付费转化的核心触点。

5.3 明确不做

不拼词书数量（打不过免费竞品）、不做词根词缀课程（内容成本高且偏离核心）、不做学习社区（冷启动期社区即死水）、不做多语言（先把英语做透）。

5.4 本节置信度

【待验证假设】竞品功能判断基于行业常识，未在本次编写中联网核实。上架前务必实际体验 3 个主要竞品并核对 5.1 的空档是否依然存在。

六、产品模块一：背单词 + 遗忘曲线复习计划

6.1 设计原则

  • 先体验，后注册。首次打开直接进入学习，学完 3 个词再引导登录。注册墙是这类产品最大的漏斗杀手。
  • 永远给一个"今天能完成"的任务量。宁可少给新词，也不让今日任务变成 200 个词。用户看到"今天 200 词"的第一反应是关闭，而不是开始。
  • 单手可操作。主要操作按钮放在屏幕下半部拇指区，这是碎片场景的硬要求。

6.2 页面结构（学生端）

页面内容关键交互
今日任务（首页）圆形进度环（已完成/总数）、三个入口：复习（N）、新词（N）、抽查（N 题）点击直接开始，无二级菜单
学习卡片（复习/新词通用）单词 + 音标 + 发音按钮；中文释义默认隐藏点击卡片翻面显示释义与例句；三档反馈按钮：忘记/模糊/秒懂
学习结算页本次学了几个、正确率、错词预览"再来 10 个"（可选）、"去抽查"（引导闭环）
词表页已学/未学/需复习三种状态分组支持按标签（中考/高考/四级）筛选
词详情页全部释义、例句、词频、历史错误次数"加入今日任务"、"标记为已掌握"

6.3 每日任务组装规则（核心逻辑）

任务是"组装"出来的，不是"排好"的。每天首次进入时按以下顺序组装：

  1. 到期复习词（按 SRS 到期时间升序，第八章）——最高优先级，必须先满足。
  2. 错词回流（昨天及更早错过、且今天到期的词）——同等优先级。
  3. 新词——填充剩余额度。

配额规则：

  • 复习额度不设硬上限（到期了就该复习），但当到期复习量超过 100 时，暂停推送新词，并在首页提示"先清复习，新词明天再来"。这条规则保护的是体验下限。
  • 新词默认 10 个/天，用户可在设置中调为 5/15/20/30。
  • 用户可手动"加练"，加练不改变 SRS 状态，只记入行为日志（避免用户靠加练刷掌握率）。

6.4 三档反馈的含义

反馈含义对 SRS 的影响次日后果
忘记完全想不起来重置到第 0 档（当天内再考一次）明天必考，且换题型
模糊想起来了但很费劲档位不变，间隔按当前档位减半当天不再考，但会提前回来
秒懂立刻反应出来直接升到下一档（可跳档）按新间隔安排

为什么用三档而不是"对/错"两档：两档会让"蒙对"和"真的会"混在一起，导致间隔被错误地拉长，用户三天后全部忘光，体验崩塌。三档给用户一个诚实的表达方式，代价只是多一个按钮。

6.5 发音与例句

  • 发音：优先使用本地 TTS（系统语音合成），零成本、无版权风险；音质不满意时再考虑引入音频资源（注意版权与流量成本）。
  • 例句：每个词至少 1 条英文例句 + 中文翻译。例句质量比词书规模更影响口碑，因为例句是用户唯一会真正读的内容。
  • 例句中目标词必须高亮，方便快速定位。

6.6 本节置信度

【待验证假设】配额数值（10 词/天、100 词阈值）为经验值，上线后需按真实完成率调整。

七、产品模块二：抽查与自测

这是本产品的差异化核心，也是投入产出比最高的模块，建议原型阶段就把它做完整。

7.1 两种模式，服务两种心理

模式触发方式判分方式心理作用
练习模式用户主动进入即时判分、可看提示学习，无压力
抽查模式（重点）家长/教练发起，或用户自己发起"考试"交卷后统一判分，过程中无任何对错反馈考试感、紧张感、结果可给别人看

交卷制是灵魂。如果过程中就告诉用户对了还是错了，用户会立刻回头改答案、并把它当成练习，压力消失，抽查的督促价值也随之消失。

7.2 三种题型的出题与判定

题型 A：选义（英译中）

  • 展示单词，4 个中文释义选项。
  • 干扰项生成规则：优先从"用户已学过的、同词性的词"中抽取，其次从"同词表的相似词（编辑距离小）"抽取。干扰项质量决定题目难度，随机抽词会让题目变得毫无意义。
  • 适用：新词首次抽查（难度最低）。

题型 B：拼写（中译英）

  • 给出中文释义 + 首字母 + 字母数占位（如 e _ _ _ _ _ _），用户输入完整单词。
  • 输入问题的处理（关键实现细节）：手机原生输入法会联想、会纠错、会自动首字母大写，这会让"拼写题"失去意义。建议实现一个应用内自绘字母键盘（26 键 + 退格 + 提交），彻底规避联想与纠错。这是本模块唯一的"必须自研"的 UI 组件。
  • 容错规则：忽略首尾空格与大小写；连字符与空格不参与判定（ice cream = icecream）；对存在英美拼写变体的词（如 color/colour）在词表里预置 variant 字段，任一写法均判对。
  • 适用：已学过 2 次以上的词。

题型 C：听写（听音写词）

  • TTS 播放发音，用户用同一个自绘键盘输入。
  • 重放限制：最多 3 次（超过则记为"提示使用"）。次数不限制的话，用户会无限重放直到听出来，题目就退化成"听力练习"。
  • 适用：已学过 3 次以上、且历史无听写错误的词。

7.3 一次抽查的结构

  • 默认 10 题，题型混合比例约 选义 3 / 拼写 5 / 听写 2，按词的历史正确率动态调整（正确率高的词更多用拼写和听写）。
  • 出题来源优先级：错词本 > 到期复习词 > 已学词随机。
  • 时间限制：建议不放硬性倒计时（会造成焦虑和作弊式乱猜），而是独立记录"本题用时"（如超过 15 秒记为"犹豫"，计入报告）。
  • 提交后：给出总分、错题逐条对照（你的答案 vs 正确答案）、并自动把错词加入次日强制复习。

7.4 抽查结果页（付费转化触点）

结果页需要同时满足两类读者：

  • 给学生的：做对了几题、哪几个词错了、错在哪（拼错了还是意思记反了）。
  • 给家长/教练的：一句话结论（"本次抽查 10 题，答对 7 题，abandon/fragile/pursue 三个词需要重点复习"）+ 一张可转发卡片。

7.5 本节置信度

【待验证假设】题型配比与 3 次重放限制为经验值；自绘键盘的必要性基于常见的移动端输入法行为推断，建议在真机上先做 5 人可用性测试确认。

八、遗忘曲线（SRS）规则

8.1 间隔序列

采用简化版 SM-2 思路（不引入难度因子等复杂参数，参数越少越可调试）：

档位:    0      1     2     3     4      5      6      7      8
间隔:  10分钟   1天   2天   4天   7天   15天   30天   60天   120天

8.2 状态流转规则

用户反馈档位变化下次复习时间备注
忘记→ 回到档 010 分钟后（当天）当天若再答对，次日恢复为档 1
模糊档位不变（不降级）当前档位对应的默认间隔 × 0.5（不低于 10 分钟）连续两次“模糊”则视为“忘记”
秒懂→ 档位 +2（上限档 8）按新档位间隔跳档上限为 2，避免一次侥幸导致间隔暴涨
逾期未复习档位不变立即到期（优先级最高）逾期超过 7 天且期间未复习，档位 -1（记忆衰减）

“模糊”为什么这样定（容易看错，单独说明）

“档位”代表记得多牢，“间隔”代表下次什么时候再见，两者是不同的东西。“模糊”同时改了两件事的一半：档位不动（这词没退步，不罚它），但这次不等满一整个默认间隔（你自己都说记得费劲了，那就早点回来）。

以档位 5（默认 15 天）为例：15 天后答“模糊”→ 档位仍是 5，下次改为 7.5 天后，而不是 15 天。

“连续两次模糊视为忘记”防的是诚实被惩罚：若每次“模糊”都保档位、只减半，会出现“间隔一直在缩短、档位却一直是 5”的情况——后台看它算已掌握（档位≥5），用户每次见它却只有点印象，数据在说谎。第二次仍然模糊，说明档位 5 这个评价本身虚高了，于是按忘记处理、回炉重学。一句话：模糊 = 这次状态不好，减半再来；模糊两次 = 上次那个档位是虚高的，退回去重学。

定档规则（实现口径，必须按这个来）：减半的基准是当前档位的默认间隔，不是“上次实际排的间隔”。即 下次间隔 = 档位默认间隔 × 0.5，而不是累乘。好处有二：不需要额外存历史间隔字段；不会出现 15 → 7.5 → 3.75 → 1.8 这种螺旋式递减的怪异间隔。代价是“模糊”连续发生的时间下限由“两次即重置”这条规则托底，而不是靠间隔自己衰减。

8.3 与每日任务的联动

  • 学习结算后立即写回每个词的 next_review_at。
  • 首页的"复习（N）"计数 = 当前时刻所有 next_review_at <= now 的词数 + 错词回流量。
  • 当日任务一旦生成就冻结快照（写入 daily_tasks），避免用户中途改设置导致任务列表跳动。

8.4 为什么不用复杂算法

FSRS 等现代算法效果更好，但：① 需要大量用户数据才能调准；② 冷启动阶段参数不准会给出诡异间隔，反而伤害体验；③ 复杂算法的调试成本对一个 3 周 MVP 不划算。先用固定序列把闭环跑通，有数据后再升级算法。数据结构设计时预留 difficulty、stability 字段以便后续迁移。

8.5 本节置信度

【待验证假设】间隔序列来自通用经验值（类似 Anki/SM-2 家族的常见配置），需在真实用户使用 2–4 周后按遗忘数据调整。

九、产品模块三：学习数据看板

9.1 指标定义（必须写死，否则"掌握率"会变成玄学）

指标定义为什么这样定义
连续打卡天数当日完成任务量 ≥ 当日配额的 80% 即计为打卡；中断一天即归零80% 阈值避免"学了 1 个词也算打卡"的自欺
掌握率档位 ≥ 5 的词数 / 已学词数（即间隔已拉到 15 天以上）用 SRS 档位定义掌握，比"测试得分"稳定，且随记忆自然变化
当日完成度已完成任务数 / 当日任务总数首页进度环的唯一数据来源
30 天活跃热力图每天一个格子，颜色深浅按当日完成任务数视觉上产生"不想断"的压力，成本极低效果好
错词率近 7 天抽查中错误题数 / 总题数抽查质量的衡量

9.2 错词本（留存关键模块）

这是用户最愿意看、也最愿意付费的功能。每条错词记录应包含：

  • 单词、释义、错误次数、最近一次错误时间、错误题型（拼错 / 意思记反 / 没听出来）。
  • 一键操作："加入今日任务""标记已掌握""移除"。
  • 分组视图：按"错误次数 ≥3（高危）""1–2 次（观察）"自动分组。高危组是抽查题的首选来源。

9.3 可转发周报卡（付费转化核心）

一张竖版卡片，包含：连续打卡天数、本周新学词数、掌握率、抽查正确率、错词 TOP10（这是家长唯一真正想看的内容）、一句鼓励语。

  • 技术上用小程序 Canvas 绘制并生成图片，用户可保存/转发到微信。
  • 这张卡同时承担三个功能：家长查看进度、家长间口碑传播、付费转化的说服材料。

9.4 本节置信度

【已验证】指标定义为本方案自定规范，内部自洽；【待验证假设】"家长最想看错词 TOP10"为推断，需在真实家长访谈中确认。

十、产品模块四：激励玩法与提醒推送

10.1 三层激励

层级机制设计要点
即时答对音效/微动画、学习结算页的完成动画每次学习 2 秒内给到正反馈，这是最有效的激励
短期每日打卡、连续天数、里程碑成就（7 天/30 天/100 天/首个 100 词）成就必须是"可达成的"，不要设计需要半年的成就
社交班级榜 / 好友榜冷启动期全站排行榜是负激励（用户永远排不到前面）。只做熟人榜（同学、家人），或干脆先不做

10.2 提醒推送：必须写清的现实约束

这是最容易被低估的技术约束，直接影响产品预期：

  • 微信小程序的订阅消息需要用户主动订阅，且一次性订阅通常只能推送一条，长期订阅受类目限制且推送频率有额度上限（具体额度以当时的微信官方文档为准）。
  • 结论："每天自动催你背单词"在小程序里做不到。产品上只能组合使用：① 订阅消息（在用户完成学习时请求订阅，下次到点提醒）；② 服务号模板消息（需额外主体）；③ 站内待办与桌面角标替代；④ 由教练/家长在群内人工提醒（真人督促反而更有效，且是付费点）。

必须在产品方案里就承认这一点，否则开发到一半才发现推送不可行，交互方案要全部返工。

10.3 打卡的"后果"设计

打卡本身没有约束力，除非它有后果。可选做法（按强度递增）：

  • 连续天数归零（弱，但成本最低）。
  • 断卡后需要"补卡"才能继续（中，需谨慎设计以免变成骚扰）。
  • 每周自动生成进度周报发给家长/教练（强，且这是天然付费点）。

推荐从第一条起步，把第三条做成付费功能。

10.4 本节置信度

【待验证假设】订阅消息的具体规则与额度必须在上线前核对微信官方最新文档；【已验证】"每日自动推送不可行"这一结论方向在订阅消息机制下成立。

接口入参返回要点

十四、商业化路径与单位经济

14.1 三条路径

路径收入来源优点主要风险
A：工具免费 + 教练服务收费抽查服务费（按次/包月）付费意愿最容易验证，起步不需要大研发重人力、毛利低、质量依赖个人
B：工具订阅制解锁高级功能（无限抽查、详细看板、去广告）毛利高、可规模化转化率是最大未知数；免费竞品会持续挤压付费点
C：混合免费工具获客 → 抽查报告与高级看板收费 → 真人教练抽成兼顾规模与早期现金流产品复杂度最高，早期不要同时做三件事

推荐：A 先行，B 跟进，C 作为终局。理由：A 能在 1 周内用人工方式验证付费意愿（见 1.2），代价最低；B 需要产品先有规模才能谈转化率；C 需要 A 和 B 都跑通。

14.2 单位经济演算示例

重要声明：以下所有数字均为"演算示例"，不是市场调研数据，不可作为决策依据。待第三章的核实工作完成后，用真实数据替换。

假设（示例值）：

  • 学员付费：99 元/月（示例值，需核实）
  • 教练时薪成本：40 元/小时（示例值，需核实）
  • 每个学员每周抽查 3 次，每次 10 题，教练批改与讲解 15 分钟/次 → 0.75 小时/周 ≈ 3.25 小时/月
  • 单学员教练成本 ≈ 3.25 × 40 = 130 元/月

在这个示例下，99 元的客单价无法覆盖 130 元的人力成本，路径 A 单独成立不了。这个演算的价值正在于此：它逼出了关键问题——

必须用产品把教练人力成本降下来。具体手段：抽查由系统自动判分（不需要人批改，人只处理错词讲解）、周报自动生成、批量催学。若能将人力投入从 3.25 小时/月压到 1 小时/月（成本 40 元），则 99 元客单价下有约 59 元毛利（该数字同样为示例演算）。

这正是本方案全部产品设计的立足点：产品存在的意义是把"人工监督"变成"系统监督 + 人工兜底"。如果只是做个背单词 App 再雇人盯，那必然会被人力成本吃掉全部毛利。

14.3 本节置信度

【待验证假设】所有数值均为示意；结论（必须压低人力成本）是定性推论，不依赖具体数值成立。

十五、合规、审核与风险

15.1 合规要点

  • 未成年人个人信息保护：仅在必要范围内采集（学习数据），不采集与学习无关的权限（通讯录、位置等）；如面向儿童，需家长授权并做数据最小化。
  • 支付与预付费：若做预付费包月，需注意消费者权益与小程序的虚拟支付限制（见 12.3）。不要一上来做长期预付卡，风险与合规成本都高。
  • 内容版权：词表通常无版权，但释义文字、例句、发音音频有版权。这是最容易踩的坑，务必使用自撰内容或明确授权的资源。
  • 教培政策敏感性：面向 K12 的学科类培训受政策约束，且政策可能变化。建议以"学习工具 + 学习陪伴"定位，避免以"学科培训"名义收费，并在上线前核实当时的政策口径（本文档不承诺政策时效性）。

function onFeedback(user, word, feedback):
    state = loadState(user, word)

    if feedback == "forgot":
        state.stage = 0
        state.nextReviewAt = now + 10min
        state.wrongCount += 1
        enqueueToday(word)              # 当天再考一次
    elif feedback == "vague":
        state.stage = state.stage       # 档位不变（不降级）
        # 基准是“当前档位的默认间隔”，不是“上次实际间隔”：不累乘、不需要历史字段
        state.nextReviewAt = now + max(interval(state.stage) * 0.5, 10min)
        if lastFeedback == "vague":
            return onFeedback(user, word, "forgot")   # 连续两次模糊视为忘记（回炉重学）
    elif feedback == "known":
        state.stage = min(state.stage + 2, 8)
        state.nextReviewAt = now + interval(state.stage)

    if overdueDays(state) > 7 and state.stage > 0:
        state.stage -= 1                # 长时间未复习，记忆衰减
    save(state)
    return state.nextReviewAt

function buildDailyTask(user, date):
    if existsTask(user, date):          # 幂等：同一天返回同一份快照
        return loadTask(user, date)

    due    = queryDueWords(user)                     # next_review_at <= today
    wrong  = queryWrongWords(user)                   # 错词回流
    limit  = user.newWordLimit                       # 默认 10
    if len(due) > 100:
        newCount = 0                                 # 保护体验：复习积压则不给新词
    else:
        newCount = min(limit, remainingBudget(user))

    task = { due: due, wrong: wrong, new: pickNewWords(user, newCount) }
    saveTask(user, date, task)
    return task
